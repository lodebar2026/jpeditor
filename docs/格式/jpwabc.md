# `.jpwabc` 格式现状

> JP-Word v5.50m 的简谱格式，本项目的一等源格式之一。**名字里的 abc 与 ABC notation 无关**
> （无 `X:`/`M:`/`K:` 字段，音符是简谱数字）。真正的 ABC 支持在 `src/abc/`。
> 模块实现见 [../模块/源格式-jpwabc.md](../模块/源格式-jpwabc.md)；新语义走 [123格式.md](123格式.md)。

**已定决策：不扩 `.jpwabc` 语法。** 曲中转调/转拍号/倚音当年都是借文法里**现成的产生式**绕过去的。

## 1. 规范散落在四处

| 位置 | 性质 |
|---|---|
| `src/jpword/Jpwabc.g4`（116 行） | **唯一形式文法**（ANTLR 4），只覆盖 `.Voice` 段。生成码在 `src/jpword/parser/`，**勿手改** |
| `src/jpword/jpwfile.ts` | **段落层规范**：哪些段头合法、各段的行语法 |
| `src/editor/help.ts:276-407` | 面向用户的记谱法说明（事实上的用户手册） |
| `src/model/tojpw.ts` / `fromjpw.ts` | **事实上的可用子集**：写出端只产生哪些记号、读入端只处理哪些 |

- 文件头签名：`// ************** JPW-ABC File Ver 1.0 (for JP-Word v5.50m) **************`
- 编码：读时 BOM 探测（回退 UTF-16LE/UTF-8），**存 UTF-16LE + BOM**
- 注释 `//`

## 2. 段结构（不是 ABC 字段，是 INI 式分段）

| 段 | 状态 | 语料占比 |
|---|---|---|
| `.Title` | ✅ `Key = {Value}` 形 | 100% |
| `.Voice` | ✅ 必需，音乐体 | 100% |
| `.Words` | ✅ 歌词 | 100% |
| `.Layout` | ✅ 只认 `LinesPerPage`（53.0%）与 `BreakPoints`（47.0%） | 100% |

## 4. 音乐体（`.Voice`）

文法核心两行：

```antlr
fragment Pitch : ( ('b'|'#'|'#b')? [0-7] ([,'gd])* ) | ('x' UniChar?) | ( 'X' (UniChar?));
Duration : '-'+ | ('_'+ '.'*) | ('.'* '_'+) | '.'+ ;
```

| 写法 | 含义 | 语料占比 |
|---|---|---|
| `1`–`7` / `0` | 唱名 / 休止 | 100% / 94.2% |
| `#4` `b7` `#b4` | 升 / 降 / **还原** | — |
| `'` `,` | 高 / 低八度点（文法里的 `g` `d` **永不被处理**） | 46.1% / 97.4% |
| `_` `-` `.` | 减时线 / 增时线 / 附点（**双附点事实上不支持**） | 90.8% / 84.2% / 76.1% |
| `( )` | 圆滑线与延音线**同形**，靠两端音高区分；可嵌套 | 100% |
| `{(3}` | 三连音（**只支持 3**，文法允许任意数字） | 4.6% |
| `{6,}` | 倚音（不带时值，排版固定按八分音符画） | — |
| `{YanYin}` | fermata | 15.0% |
| `$(true)` / 第 4 参 true | 换行 / 换页 | 100% / 88.2% |
| `"1=A"` | 曲中转调（借 `STRING` 产生式） | — |
| `3/4` | 曲中转拍号（借 `TimeSig` 产生式） | — |
| `[\|]` | **不可见小节线**，必须照写——少一根会把两小节并成一个 | 3.2% |
| `\|` `\|\|` `\|]` `\|:` `:\|` | 小节线 | 99.8% / 0.7% / 99.8% / 2.5% / 5.8% |

### `)` 是二义符号

圆滑线收尾 还是 三连音收尾？判据：**前面的音符还欠着 `(` 就先收弧，欠完了才轮到三连音**
（本音符自己开的 `(` 不算数）。反例是 158《一件礼物》。

### 无点「1」的绝对音高

落在 **B3(59) … A4(69)** 这一个八度里；**只有主音字母是 B 的调（B / bB）整体降一个八度**，A / bA 不降。
依据是《简谱通用规范》第 23–24 页。判据在 `score.ts::getBasePitch` 与 `jppitch.ts::jpTonicOctaveShift`
两处，**必须同源**。

## 5. `.Words`：歌词

段头文法（sticky 锚定行首）：

```
W(\d+)(-(\d+))?(\([0-9a-zA-Z.,]+\))?(@(\d+),(\d+))?(\([0-9a-zA-Z.,]+\))?:
```

| 写法 | 含义 | 语料占比 |
|---|---|---|
| `W1:` | 第 1 段 | 100% |
| `W1-6:` | 段号区间，这行词供第 1–6 段共用 | **0.2%** |
| `@m,n` | 从第 m 小节第 n 个音符起对齐 | **100%**（每条段头都带） |
| `/` | 本音符不换字（melisma 续记号） | 81.5% |
| `{多字}` | 整组当一个音节 | 50.2% |
| `{多字[对齐位]}` | 组内标对齐位 | 0.9%，**解析后无消费方** |
| 段头的 `(…)` 控制串 | — | 0%，**解析后无消费方** |

`-`、空格、`(`、`)` 在歌词行被跳过；ASCII 字母连写自动成词；
收尾标点贴到前一个音节、不占音符格；左引号搬到下一个音节——**段首**的「“」前面没有音节可贴，
也只贴到下一个音节、不自成一格（语料 5 首，旧实现留下空格，整段错一个音、写出再读回每轮再错一格）。

JP-Word 存的是 **Windows 换行（`\r\n`）**，读入端按行切完要去掉行尾 `\r`：否则歌词段把每个行尾的 `\r`
当成一个音节，整段往后错一格、段末丢字（语料 567 份，`jpwfile.ts::JpwFile.parse`）。

## 6. `.Repeat`：演唱顺序表（本格式最独特的一层）

谱面的 `|: :|` 与房号**只是谱面记号**，真正决定「按什么顺序唱、唱第几段词」的是这一段。

| 写法 | 含义 | 语料 |
|---|---|---|
| `1-4V1` | 第 1 遍唱第 1–4 小节、配第 1 段词 | 41 条 / 7 首 |
| `1-4V1P` | `P` = 这一遍唱完**换页** | 有 |
| `11.2-20V4` | 从第 11 小节**第 2 个音符**接入（skip） | **0** |
| `11-20.1V5` | 只唱到第 20 小节第 1 个音符（limit） | **0** |
| 逗号 | 可当行分隔 | — |

**小节号有 0 起与 1 起两种写法**：500 首里带 `.Repeat` 的 7 份 JP-Word 文件一律 **0 起**（`0-22V1`，最大号 = 小节数 − 1），
本仓库测试语料与写出端（`tojpw.ts`）是 1 起；文件头版本相同，看不出由什么决定。0 在 1 起写法里不可能出现、
第一遍总从头唱故 0 起写法必有 `0-`，读入端（`fromjpw.ts::convertRepeat`）据此「出现 0 就整份按 0 起」，模型里一律 1 起。
按 1 起硬读 0 起文件，演唱顺序里有第 −1 小节，排版抛错。

- 遍数分布：0 遍 98.8%、3/4/5/7/9 遍各 1–2 首。
- **段号非顺序**（第 n 遍≠第 n 段词）：**6 首**——ABC 的「相邻 `w:` 依次对应」表达不了这个。
- 导出 MusicXML 时由 `deriveVoltas()` 反推 `<ending>`；skip/limit **表达不了**（`<ending>` 只能整小节）。

## 8. 已知缺陷

1. **`{C:…}` 不剥离会污染音符解析**：逐字符扫描时 `{C:1.5}` 里的 `1`/`5` 被当音高、`.` 被当附点。
   500 首语料里 0 例，但真实 JP-Word 文件可能带。
2. **`::` / `:|:` 抛错**导致整首载入失败（文法允许、导入端 `throw`）。语料 0 例。
（原第 3 条「写出端产生 `|:[1` 读不回」随旧写出端删除：现写出端 `tojpw.ts` 不写房号，反复与分遍经 `.Repeat` 表达。）

两条的真实影响面都已用 568 首语料量过（见 `node scripts/census-123.mjs`），故优先级定为低。

## 9. 表达力边界

**装不下**：和弦、力度与渐强渐弱、多声部（`.Voice` 只有单声部，导出时只导第一声部并提示）、
副标题、曲号、自由节奏/散板。这些是 [123格式.md](123格式.md) 存在的直接理由。
