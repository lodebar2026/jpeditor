# 导出

## 职责

页面树/模型 → PNG / PDF / 矢量 PPTX / MIDI / MusicXML / `.jpwabc` / 文本谱原文。

## 入口

| 函数/文件 | 作用 |
|---|---|
| `EXPORT_ITEMS` | `src/editor/export.ts:255` 导出菜单（PPTX / MIDI / MusicXML / JPWABC / PNG / PDF） |
| `buildPptx(painter)` | `src/editor/pptx.ts`（455 行）页面树 → OOXML 形状，fflate 打包 |
| `scoreToMidi(score, opts)` | `src/score/midi.ts:67` 标准 MIDI 字节（与试听共用） |
| `scoreToMusicXml` / `patchMusicXml` | → [源格式-musicxml与abc.md](源格式-musicxml与abc.md) |
| `scoreToJpwabc` | `src/score/jpscore.ts` |

| `writePdf` | `scripts/pdfwrite.mjs`（成书路，**全仓唯一写 PDF 的地方**） |

## 关键判据

- **PPTX 取展开档**那一套（`export.ts::pptxPainter`），哪怕屏幕正停在原样档。
- **PPTX 有一层字体度量修正**（`TARGET_ADVANCE`/`TARGET_DESCENT`）：排版是拿浏览器里的 PingFang SC
  量的，而 .pptx 里写的是 Microsoft YaHei（投影机与 Windows 上真正会用的那份）。
  两套字的 descent（0.357 vs 0.2617 em）与数字宽（PingFang 的「1」只有 0.401 em，YaHei 等宽 0.5864 em）
  都不同，不修正则文字整体下沉一格、「1」的八度点与减时线明显偏左偏短。
  做法：**按目标字体的 descent 定文本框底、把音符数字居中到目标宽度的框里**（框心落在 `JpNumber.cx`）。
- **歌词收尾标点并进前一个字并换半角形**（`TRAIL_PUNCT`）——YaHei 的全角逗号墨迹在字身正中，
  单独成框会顶到下一个字。
- 倚音底缘按目标字体的墨迹顶对齐（`jpLegacyDigitInkTop`）。
- 背景色白底一律不铺；非白则 PNG 铺画布底、混排 PDF 插满幅 rect、PPTX 写 `<p:bg>`。
- `.jpwabc` 只支持单声部，多声部时只导第一声部并 `setStatus` 提示。
- MusicXML 一律**有底本就 patch**。

## 回归

```bash
node scripts/pptx-ref-check.mjs   # 拆开导出的 .pptx 量几何，与 2019 成品 ppt500 同判据
node scripts/pptx-check.mjs       # 两档版面
node scripts/pptx-export.mjs      # 500 首批量导出
node scripts/xml-roundtrip.mjs
node scripts/omr-export-check.mjs
```
