# 源格式：ABC 家族（123 与标准 ABC）

**格式规范** → [../格式/123格式.md](../格式/123格式.md)（123 是 ABC 方言，§0 说清了为什么）

## 职责

123 与标准 ABC 的**词法、解析、写出**。两者只有音乐体不同，所以这里是「基类 + 两个方言」，
不是两套实现。

## 为什么 ABC 不经 MusicXML 转一手

`src/abc/abc2xml.ts`（abc2xml.py 的忠实移植）早就能把 `.abc` 转成 MusicXML。但那条路
**把源字符偏移丢光了**：

- 编辑器的双向定位（代码区光标 ↔ 谱面元素，见 [编辑器与播放.md](编辑器与播放.md)）
  最多做到小节级
- 往返只能「原文照抄」或「全量重写」二选一，改一处就得重排整份

所以 `.abc` 要原生解析直出 `ScoreDoc`。而这与写出端的继承复用正好对称：
123 与 ABC 的头部字段、`V:`/`w:`/`P:`、小节线与房号、装饰、和弦与注记、倚音、多连音
**全部同源**，`j123/lex.ts` + `parse.ts` 实现的正是这些。

## 方言差在哪（**只有这张表里的**）

| | 123 | ABC |
|---|---|---|
| 音符 | 调内度数 `1`–`7` | 绝对音名 `A`–`G` / `a`–`g`（大写低八度） |
| 变音 | 前置 `#` `b` `n` | 前置 `^` `_` `=` |
| 时值 | `_` 减时线、`.` 附点（相对） | `2` `/2` `3/2` 分数（相对 `L:`） |
| `-` | **增时线**（加一拍） | **tie**（延音线） |
| 休止 | `0` | `z`（带时值）/ `Z`（整小节数） |
| 多连音 | `(3:` **冒号必需** | `(3` 可省 |
| 同时发声 | 另起声部 | `[CEG]` |
| 换行 | 显式 `$` / `$$` | **代码换行即谱面换行**（§6.1 的 `I:linebreak <EOL>`） |
| 歌词音节分隔 | CJK 连写 | 空格；词内 `-` |
| 歌词跳音符 | `/` | `*` |
| 调号 | 首调 `1=F` | 音名 `F` / `Em` |

`-` 与 `_` 那两行是**硬冲突**——123 的音乐体因此不是合法 ABC 音乐体，这是方言的代价，
也是唯一的代价。

## 关键判据

- **`abc2xml.ts` 不删**，两个用途：① 语义对照基准（`abc-check.mjs` 与它逐字节比）；
  ② **fallback**——原生解析读不出音符或抛异常时，`app.ts::_reloadAbcFallback` 自动回落，
  谱面照样看得到，但降级为「定位只到小节」并在状态栏说明。沿用项目既有的兜底模式
  （patch 对齐失败兜底全量、`sniffDialect` 认不出宁可不动）。
  **转正判据：回落率 < 1%**（`abc-native-check.mjs`）。
- **解析侧刻意不对称**：写出端两个方言都由 `abcfamily` 出，读入端只有 `abcfamily` 一条，
  `abc2xml` 平行留着。这不是遗漏，是拿覆盖面换来的保险。
- **ABC 只给绝对音高，简谱那侧要度数**：`parseAbcFamily` 收尾时用
  `jianpu.ts::degreeFromPitch` 补出 `degree`。**不许在别处另写一份换算**——
  那一处与 `jppitch.ts` 同源，「两份实现一旦漂移，往返数字就会错」。
- **落单的 `]` 读成收尾线**：规范里没有，但野外的 ABC 常这么写（`… z2]`）。
  `[|]`/`|]` 与和弦 `[CEG]`、行内字段 `[K:G]` 都在它之前被吃掉，所以走到那一步的一定是收尾线。
- **ABC 末小节不写换行标记**：那是个真换行，末尾多一个就成空行，而 **ABC 的空行会终止曲体**，
  后面的 `w:` 歌词行就成了孤儿。123 那一档照写 `$`（无害，且要保幂等）。
- **写出端固定 `L:1/8`**：写出要幂等就不能让默认音长随内容浮动。读入端照样认任意 `L:`。
- **`V:` 的声部号在冒号之后**（`V:1`、`V:2 name="Bass"`），不写在冒号前面。
  只认前缀数字会让几个声部全归声部 1、拼成一串。
- **歌词行不带段号**：`w:` 按出现顺序编段（ABC §5.1），同段拆几条写用 `+:` 续行（ABC §3.1.18）；
  段号区间与副歌行写出时**逐段各抄一遍**，中间空着的段写一条空 `w:` 顶住段位。
- **`V:n` 再次出现是续写**（ABC 语义）：`parse.ts` 按声部号存 `PartBuild`，开着的弧/多连音/房号/欠着的和弦记号
  **各声部一份**——交错写法里 `V:1` 的弧跨行、中间隔着 `V:2` 的行，共用一份会配错对。
- **`w:` 对齐前一行曲**（ABC §5.1）：两种方言共用歌词块规则（见 [源格式-123](源格式-123.md)）。
  ABC 每个代码行都是换行，所以一条音乐行就是一块，正是标准语义；以前从全曲第一个音起挂，交错写的 ABC 读进来全错位。
  写出端两种方言都逐系统交错写。

## 已知限制

- ABC 的 `Q:3/8=60` 读成 `Q:1/4=60`：`ScoreDoc.tempos` 只存数值，参照音符长度没有位置
- `K:D bass` 这类 clef/修饰读进来就丢（`clef` 字段已定义未填充，等五线谱侧那一轮）
- `~`（一音多字）读回来会被当成词的一部分，往返稳定但与原文不同形
- 123 那一档的**拉丁歌词**仍是连写（`lyricSeparator` 为空串）——那是既有行为，
  中文语料碰不到；要改得连 `parseLyricLine` 一起看
- ABC 的 `%%score`、`U:` 自定义符号、宏未读入（`abc2xml` 读得了，走 fallback）
