# 源格式：123（`.123`）

**格式规范** → [../格式/123格式.md](../格式/123格式.md)

## 职责

123 格式的词法、解析、输出。123 是**简谱主格式**（与之对应，MusicXML 是五线谱主格式），
ABC 方言：沿用 ABC 的字段头与记号体系，音乐体换成简谱原语。

## 入口

> **词法与写出端已抽成 ABC 家族的基类 + 方言**，见
> [源格式-abc家族.md](源格式-abc家族.md)。本页只留 123 自己的判据。

| 文件 | 作用 |
|---|---|
| `src/j123/lex.ts` | **薄壳** → `abcfamily/dialect123.ts` |
| `src/j123/fields.ts` | 字段表、中文别名、`K:`/`M:`/`Q:` 解析、`I:` 指令（含 `I:playorder`） |
| `src/j123/parse.ts` | 组装：小节切分、时值、符杠分组、Mark 配对、歌词对位 → `ScoreDoc`。**两种方言共用**（`parseAbcFamily`），`parse123` 是它的薄壳 |
| `src/j123/emit.ts` | **薄壳** → `abcfamily/emit123.ts` |
| `src/j123/highlight.ts` | 编辑器语法高亮（**独立的轻量扫描，不复用 `lex.ts`/`parse.ts`**） |

## 关键判据

- **两处与 ABC 的硬冲突**：`-` 在 ABC 是 tie、123 是增时线；`_` 在 ABC 是降号、123 是减时线。
  所以 123 的音乐体不是合法 ABC 音乐体——这是方言的代价，也是唯一的代价。
- **`(N:` 的冒号必需**：简谱音符是数字，裸 `(3` 与「圆滑线 + 音符 3」歧义。完整形要**两个冒号**
  （`(3:2:3`），不支持 `(3:2`——否则 `(3:1 2 3` 里的 `:1` 会被当成 normal=1。
  两个既有格式都回避过这个歧义（`.jpwabc` 写 `{(3}`、文本谱写 `(y3`）。
- **`)` 是二义符号**：收圆滑线还是收多连音？判据照 `.jpwabc` 那条——
  「前面的音符还欠着 `(` 就先收弧，欠完了才轮到三连音」。多连音按计数自动收尾后紧随的 `)` 静默消费。
- **空白不表示符杠分组**：符杠按拍自动算（排版 `beamGroupsOf`），123 不设 `Chord.beamGroup`、
  不设 `~`/`^` 控制符，写出端音符一律空格隔开。只有 ABC 方言按 §4.7 用空白分组（`ParseDialect.spaceBeams`）。
  反引号 `` ` `` 只为可读性，扫描时丢掉。
- **不带引号的和弦**（`F 3- 2`）：大写 A–G 开头、**到空白为止**、后面必须跟空格；与 `"F"` 出同一种 token
  （`dialect123.ts::scanBareChord`）。A–G 在 123 音乐体里原本没被占用，所以不冲突；到空白为止是因为
  `G71`、`Bb3` 这种粘连切不开。名字不合 `BARE_CHORD_RE` 报诊断但仍当和弦。写出端合规就不带引号（`N.C.` 仍带）。
- **写出端 `$` 后换行**：一行曲一行源码，方便与源图对照；123 的代码换行不是谱面换行（`lineEndIsBreak: false`），读回不变。
  版本头 `%123-1.0` 读入时当注释，**可以不写**；写出端照写。
- **小节线的归属**：小节里还没有元素时，小节线算**左线**（不收尾）——否则行首的 `|` 会凭空
  造出一个空小节。`fromjpw.ts`（原 `fromscore.ts`）也按这条规则重切小节，两侧口径必须一致，否则永远不幂等。
- **`$` 的语义是「这一小节之后换行」**：小节线通常先到、新小节还空着，所以要挂到刚收尾的那一个。
- **一行曲一行词**（规范 §5.1）：读入端按「歌词块」对位——块从上一批 `w` 行之后或上一个 `$` 之后的第一条音乐行起，
  紧跟的 `w` 行从块首对位格起挂（`parse.ts::LyricBlock`）；写出端按第一个声部的 `$` 切系统，
  每个系统写音乐行、再写这一行各段的 `w` 行（`emit.ts::lyricLines(part, …, from, to)`）。
  **块必须在 `$` 处也断开**：只按「跟过 `w`」断，没词的前奏行会和下一行并成一块，下一行的词从前奏第一个音挂起
  （主祢真伟大首行就是这样）。对位格判据读写两端共用 `abcfamily/lyricslot.ts::isLyricSlot`，别各写一份。
  行末 melisma 写 `主_`，那个 `_` 落在块外，**只算有字的超出**才报 `lyric-overflow`。
  词内断音节跨行时行末照写 `-`；不包 `{}` 的拉丁字里的字面 `-` `/` 写成 `\-` `\/`，其后要空格
  （番茄文本谱把 `How-` 整个存进字里，不转义读回会拆散、转义不空格又会粘成一个音节）。
  跳音符是方言钩子 `ParseDialect.lyricSkip`（123 `/`、ABC `*`）；123 里的旧 `*` 报 `lyric-old-skip` 仍当跳音符。
  不支持 `@m,n` 锚点。
- **歌词对位**：CJK 连写逐字成音节（对 ABC §5.1 的扩展）；emit 时**行内空位必须补 `/`**，
  否则中间空一个音符就会让后面所有字前移一格、末尾溢出丢字；多字并一格要包 `{}`，
  否则读回时被拆散——但「一个字 + 标点」（`哦，` `“主`）读回本就是一个音节，**不包**；
  后面接词内 `-` 的仍包（`{来”}-`，CJK 分支不认字后的 `-`）。判定口径与读入端同一份（`common/cjkpunct.ts` 的 `isLyric*`）；
  CJK 连写，但**两个拉丁音节相邻必须空格**（`主a b`），否则读回粘成一个音节；`extend`（`字_`）已经占掉了下一格，不要再补 `/`。
  音节多于音符时报 `lyric-overflow`（ABC §5.1 要求「warn the user」，静默丢字在迁移时是灾难）。
  **引号与标点不占音符格**（直引号 `"` 分不出开闭，一律贴前字）；行首没有前字可并的标点走
  `Lyric.leadingPunctuation`，**不能并进 `text`**——并进去会改变音节字数，让「多字并一格要包 `{}`」
  的判断在往返中翻来覆去。
- **多曲文件每首都要写 `X:`**：123 的分曲就靠它（同 ABC tunebook）。文本谱用 `-----` 分曲且
  大多没有曲号，不补序号会让几首连成一片、读回只剩一首。
- **`x` 是 `Chord`、`y` 是 `Space`**：`x`（不可见休止）有时值、占对位格（对应文本谱的隐藏休止 `8`）；
  `y` 无时值、不占格，只为挂和弦。弄混会让歌词错一格。
- **弧可以在增时线上起止**（`(6,_ 1_)` 这种写法很常见）：增时线有自己的 id，emit 时要一并查
  `slurStart`/`slurEnd`，否则写出只有 `(` 没有 `)` 的非法 123。
- **调号拼写由语义层给**（`jianpu.ts::keySpelling`）：MusicXML 来源的 `Key` 只有 `fifths`，写出端以前回落成 `C`，
  D 大调的谱转出来是 `K:1=C`、整首移调（500 首 502 份）。**曲中转调/转拍号写行内 `[K:]` `[M:]`**
  （`emit.ts::partSystems`），以前不写，019《拥戴祂为王》A♭ 转 A 后半首差半音。
- **混合拍写在一条 `M:` 里**（`emit123.ts::timeValue` / `fields.ts::parseTimes`）：页眉并排印着的
  几个拍号都写出（`M:3/4 4/4 混合拍`，首个是 `Song.time`、其余 `Song.extraTimes`、说明文字
  `Song.timeNote`），辅助拍号照原样带括号。**这是 123 的扩展，ABC 那一档仍只写头一个**
  （基类 `timeValue` 默认如此）。单个拍号与 `C`/`C|`/`none` 仍走 `parseTime`，说明文字只收短中文，
  别的剩字一律退回去报 `bad-time`。
- **一个声部只写简谱印的那一路**（`emit123.ts::emits` / `chordNotes`：`melodyLane` 那一路、每个和弦最高音）。
  123 没有音符堆，以前把同一 `<chord/>` 的几个音挨着写成 `35`，读回成两个先后的音、时值翻倍；
  丢掉的内声部与第二 voice 由 `planSave` 报 `noteStack`。
  验：`jianpu-semantic-check` 的「往返音高」——MusicXML → 123 → MusicXML 旋律音高逐个不变，5 个语料目录 0 份。

## 编辑器接入

`.123` 在编辑器里是**原文即主体**：拖进来原文直接进代码区，存盘把原文按 UTF-8 写回同一文件
（`isConvertedFile` 不含 `123`，所以 `filePath` 不清）。每格式的差异走
`src/editor/formats.ts` 的适配器表，见 [编辑器与播放.md](编辑器与播放.md)。

- **排版直接吃 `ScoreDoc`**：`parse123` → `ScoreDoc` → 与文本谱共用同一对排版器
  （原样档 `PuPainter.load(ScoreDoc)` / 展开档 `jianpuInputOfDoc` → `ExpandedPainter`）。档位旋钮也跟文本谱同一个（`puProfile`）。
- **按乐句重排**：断点写进模型的换行位再整份 `emit123` 重出（`model/relayout.ts`）。
  `$` 只落在小节之后，所以小节中间的断点挪到下一根小节线；歌词行跟着 `$` 重新归行是写出端本来就做的事。
  **注释不进模型**，重出会丢，所以再按「跟着哪个和弦」缝回去（`spliceComments`）。
- **诊断进状态栏**：`ScoreDoc.diagnostics` 里 `severity === "error"` 的拦排版，
  其余只提示（`第 N 行 …`）——与文本谱同一套口径，谱面往往仍然是对的。
- **高亮是独立扫描**：`j123/highlight.ts` 与 `pu/highlight.ts` 同一条判据——高亮要能在半截、
  写错的文本上照样上色，解析器该报诊断就得报，两者目标不同。行首前缀按宽松形认。
  CSS 类与 `.jpwabc`/文本谱共用一套，三种格式观感一致。

**验**：`node scripts/j123-shot.mjs`（不给参数就从内置样例谱现造一份 `.123` 走一遍）。

## 已知限制
- 残留 27 份不幂等与 25 份无法表达（都在 0.2% 以下，逐条在覆盖率报表里）
- 一项**上游限制**（不是 123 的缺口）：`parsePu` 不保留 `"1."` 这类段号标记的 annotation（1932 份记为降级）
- 段号区间（`.jpwabc` 的 `W1-6:`、文本谱 `C1-2:`）123 不表达：写出时**逐段各抄一遍**
  （规范 §11；ABC 只有裸 `w:`，段号按出现顺序）
- 与文本谱共用 `PuPainter`，没有 123 专用排版器；观感调整属样式层 R1
- 写不出承接前音的增时线（文本谱 `5 - | - -`），不需要支持
- 整篇简繁转换这一档没有（`convertJpwabc` 认的是 `.jpwabc` 段结构）
- 「每页行数」设置这一档没有（123 是 `I:linesperpage`，等直通那轮再接）
