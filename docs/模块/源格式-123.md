# 源格式：123（`.123`）

**格式规范** → [../格式/123格式.md](../格式/123格式.md)

## 职责

123 格式的词法、解析、输出。123 是**简谱主格式**（与之对应，MusicXML 是五线谱主格式），
ABC 方言：沿用 ABC 的字段头与记号体系，音乐体换成简谱原语。

## 入口

| 文件 | 作用 |
|---|---|
| `src/j123/lex.ts` | 音乐体词法：一行 → token 流 |
| `src/j123/fields.ts` | 字段表、中文别名、`K:`/`M:`/`Q:` 解析、`I:` 指令（含 `I:playorder`） |
| `src/j123/parse.ts` | 组装：小节切分、时值、符杠分组、Mark 配对、歌词对位 → `ScoreDoc` |
| `src/j123/emit.ts` | `ScoreDoc` → `.123` 文本 |

## 关键判据

- **两处与 ABC 的硬冲突**：`-` 在 ABC 是 tie、123 是增时线；`_` 在 ABC 是降号、123 是减时线。
  所以 123 的音乐体不是合法 ABC 音乐体——这是方言的代价，也是唯一的代价。
- **`(N:` 的冒号必需**：简谱音符是数字，裸 `(3` 与「圆滑线 + 音符 3」歧义。完整形要**两个冒号**
  （`(3:2:3`），不支持 `(3:2`——否则 `(3:1 2 3` 里的 `:1` 会被当成 normal=1。
  两个既有格式都回避过这个歧义（`.jpwabc` 写 `{(3}`、文本谱写 `(y3`）。
- **`)` 是二义符号**：收圆滑线还是收多连音？判据照 `.jpwabc` 那条——
  「前面的音符还欠着 `(` 就先收弧，欠完了才轮到三连音」。多连音按计数自动收尾后紧随的 `)` 静默消费。
- **符杠分组由空白决定**（ABC §4.7），落成 `Chord.beamGroup`，不设 `~`/`^` 控制符。
  反引号 `` ` `` 只为可读性，扫描时丢掉。
- **小节线的归属**：小节里还没有元素时，小节线算**左线**（不收尾）——否则行首的 `|` 会凭空
  造出一个空小节。`fromscore.ts` 也按这条规则重切小节，两侧口径必须一致，否则永远不幂等。
- **`$` 的语义是「这一小节之后换行」**：小节线通常先到、新小节还空着，所以要挂到刚收尾的那一个。
- **歌词对位**：CJK 连写逐字成音节（对 ABC §5.1 的扩展）；emit 时**空位必须补 `*`**，
  否则中间空一个音符就会让后面所有字前移一格、末尾溢出丢字；多字并一格要包 `{}`，
  否则读回时被拆散；`extend`（`字_`）已经占掉了下一格，不要再补 `*`。
  音节多于音符时报 `lyric-overflow`（ABC §5.1 要求「warn the user」，静默丢字在迁移时是灾难）。

## 回归

```bash
npm run build:cli
PU_CORPUS=<文本谱语料根> HYMN500=<500首语料根> node scripts/j123-migrate.mjs   # 迁移 + 覆盖率报表
node scripts/census-123.mjs    # 语料特征盘点（规范条目的来源）
```

**现状**：500 首的 568 份 `.jpwabc` 与文本谱语料全部转换成功；`.jpwabc` 侧往返幂等 568/568、
零无法表达项。详见 `testdata/j123-coverage.md`（本地产物）。
