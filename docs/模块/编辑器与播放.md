# 编辑器与播放

## 职责

编辑器控制器（编辑 ↔ 实时重排 ↔ 翻页 ↔ 文件 I/O）、点选高亮、可视化编辑（谱面上直接改谱）、设置、播放、Tauri 外壳。

## 源格式适配器（`formats.ts`）

打开的源格式有五种（`.jpwabc` / 文本谱 / `.123` / `.abc` / `.musicxml`，`docFormat` 记当前是哪种）。
**因格式而异的那些差异全收在这张表里**：高亮扩展、读写编解码、默认扩展名、标题取法、
格式标签、档位旋钮（`jpProfile` 还是 `puProfile`）、能力位、重排入口。

以前这些是 `app.ts` 里散在约二十处的 `docFormat === "pu"` 三目式，加第三种格式
每处都要再分一次叉。**别再往 `app.ts` 里加这种三目式**——该加的是 `FormatCaps` 的一位。

| 能力位 | 含义 |
|---|---|
| `textEditor` | 有没有代码区。`.musicxml` 没有：打开只看谱面，「转成 … 编辑」换成文本格式（`App.convertToTextDoc`，与格式下拉同一条路、切得回原文），五线谱编辑经 `App.editScoreDoc` 改模型、整份重写 XML |
| `hanConvert` | 整篇简繁转换（`convertJpwabc` 认 `.Title`/`.Words` 段结构） |
| `layout` | 谱面走哪套排版：`scoredoc`（文本谱、123、ABC、MusicXML：展开档 `jianpuInputOfDoc` → `ExpandedPainter`；原样档看 `originalEngine`）或 `jpwabc`（`jianpuInputOfJpw` → 简谱引擎两档） |
| `originalEngine` | `scoredoc` 原样档用哪个排版器：`jianpu`（123、ABC；投影后交 `JinpuPainter`，多声部回落 `PuPainter`）或 `pu`（文本谱、MusicXML） |
| `phraseRelayout` | 有没有「按乐句重排」。怎么写回原文由 `FormatAdapter.relayoutText` 给：文本谱搬原文片段（`pu/relayout.ts`）、123/ABC 写模型再整份重出、`.jpwabc` 只挪 `.Voice` 的 `$`（`model/relayout.ts`）；`.musicxml` 没有代码区，不给 |

五线谱/混排**不是能力位**：所有格式都有。`.musicxml` 用打开时读的那份模型；文本格式（含简谱识别落地的 123）
进这两档时由 `App._ensureMixedDoc` 把当前源文经 `export.ts::sourceMusicXmlBare` 投成 MusicXML 再读回（源文没变不重做），
在这两档里代码区仍可编辑、改了就重新派生重排；打开文件时原来在这两档就留在那档（`.musicxml` 同口径）。
派生的 XML **不带**版面坐标，混排排版器见不到坐标就自动铺排（`layoutpass.ts`）；换行照**简谱视图实际排出的行**
（`App.jianpuLineStarts`：另造一个排版器按当前档与纸排一遍取各行首音，经 `ToXmlOptions.lineStarts` 落到小节上），
自动铺排拿它当优选断点。纸取设置里原样档那张（`App.staffPage`，文本谱取它自己那一档；长图不分页）。
派生缓存按「源文 + 简谱的档、纸、字号」（`_mixedDeriveKey`），这些一变就重新派生。

真正因格式而异的**算法**（`reloadPu` / `reload123` / 乐句重排 / 播放高亮走 AST 索引）
仍留在 `app.ts`，适配器只负责分派。

## 源码格式下拉（`formatswitch.ts`）

代码区标题栏的格式标签位置上是一个下拉（`#doc-format-field`，有可切的格式时顶掉标签），
**打开的文件与识别结果共用**。下拉本身（控件、显隐、「手改过会丢」的确认）只有一份，切换怎么做由来源各自实现 `FormatSource`：

| 来源 | 真身 | 切到别的格式 | 切回 |
|---|---|---|---|
| 打开的文件（`FileFormatSource`，`App.importBytes` 装上） | **原文** | 从原文的模型写出；先列装不下的（`planSave`），文件路径清空（存盘走另存为，原文件不动） | 「原文」那一项：**逐字还原**原文与文件路径 |
| 识别结果（`OmrController`） | `RecognizedScore` | 从识别结果重出文本，**不重跑识别**；选择记进 `omrFormat` | 同左（没有「原文」） |

- 目标清单是转换目标表 `model/convert.ts::CONVERT_TARGETS`（123 / JPWABC / ABC / 番茄 / 诗歌本），另存为也用它。
- **在原格式里改过再切走，以改过的文本为准**（它就是新的原文，模型重建）；在转出来的格式里改过再切，先问一声再丢——
  转出来的文本不是真身，从它再转一次只会越转越丢。
- `.musicxml` 原文没有代码区，下拉里的「MusicXML（原文）」切回去时代码区收起；从导出菜单「转成 … 编辑」进来的是同一个来源。
- 落地统一走 `App.adoptText(format, text, filePath)`（识别产物的 123 另走 `importOmrDoc`，报它装不下的东西）。

## 双向定位（`sync.ts`）

代码区光标移到某个音符上，谱面上那个音符亮起来；点谱面上的音符，代码区光标跳过去。
选区同理（区间内的音符全亮）。适用于有代码区的四种格式（文本谱、123、ABC、`.jpwabc`）的简谱两档。

索引条目分七种（`SyncEntry.kind`）：音符、歌词、增时线、小节线、挂载记号（和弦名、装饰、注记、圆滑线的 `(` 与 `)`）、换行符、页眉字段（见下文可视化编辑）。
后四种的原文位置是为可视化编辑补记的（`AttachedSource`、`Mark.openSource/closeSource`、`Part.breakSources`，
只给编辑用，排版与写出端不读）。增时线、小节线、弧借宿主音符的 `<g>`；和弦名、装饰、注记按类名在音符格里认出自己的
（`chord-group`/`artic`、文本谱排版器的 `chord`/`ornament`/`annotation`，`App._markPartEl`）。
**`syncEntries()`（`sync-check` 用）只给音符与歌词**。

| 方向 | 怎么走 |
|---|---|
| 文本 → 谱面 | 光标偏移 → `SyncIndex.range()` 二分 → 条目 → 已缓存的 `<g>` → 加 `.cursor-at` |
| 谱面 → 文本 | 点击事件从 `ev.target` 往上找 `<g>` → 条目 → `view.dispatch({selection})` |

**几条判据**：

- 索引建在 `ScoreDoc` 的 `source: SourceSpan` 上，条目按**元素 id** 认；音节配给哪个音符取排版行视图
  （`pu/slots.ts::docView` 的 `syllableOwner`），与排版器、引擎输入同一份。`PuPainter.noteGroupEl(id)` /
  简谱引擎 `ScorePainter.chordGroupEl(id)`（引擎输入的和弦带元素 id）取 `<g>`，不必动排版。试听高亮同样按 id。
- **不进 `PagePainter` 接口**：架构 §3.1 明写「高亮不在接口里，三者语义不同」。
- 谱面那侧**按 `<g>` 认、靠冒泡**，不依赖 `pickPage` 的几何拾取——原样档根本没有 `pickPage`，
  两档因此共用同一条路径。`_onSyncClick` 必须留在 `onPageClick` 最前面。
- 走 CSS 类、**不重渲染**；`.cursor-at` 排在 `.playing` 之前，试听时发声的那个盖过光标色。
- 防回环：`_syncing` 标志；文档变更时不在监听里同步（索引还是旧偏移），
  等 `reload` 重建索引后由 `_buildSync` 刷一次。

## 可视化编辑（`editor/visual/`）

在谱面上直接选中、插入、修改音符与记号；操作说明在帮助的「可视化编辑」页（快捷键表由动作表生成）。

| 文件 | 作用 |
|---|---|
| `keys.ts` | **动作表**：快捷键、名字、说明只写这一份；键盘、帮助、右键菜单、记号面板都从它取 |
| `controller.ts` | `VisualEditController`：谱面焦点下的键盘、点击、右键；经宿主接口 `VisualHost` 向 App 要能力 |
| `cursor.ts` / `overlay.ts` | 两种光标在代码区 / 谱面的画法；换行符号、拍数不对的小节标红（叠加层，不重排版） |
| `ops.ts` / `breaks.ts` | 动作 → 对原文的局部补丁（与格式无关）；换行增删连带拆并歌词行 |
| `dialect.ts` + `dialects/` | **因格式而异的全在这里**（`FormatAdapter.editDialect`）：123、ABC、`.jpwabc`、文本谱各一份 |
| `menu.ts` / `preview.ts` | 右键菜单与记号面板；按键即发声 |

**判据**：

- **源码仍是真身**：每个动作落成对代码区原文的局部补丁（`userEvent: "input.visual"`），不走「改模型再整份重出」
  （那样会丢注释与手写排版）。撤销重做就是代码区那份 history；补丁后立即重排（`reloadNow`），不等 200ms 防抖。
- **光标状态只存一份**：代码区选区。非空 = 编辑模式（方块），空 = 插入模式（竖线）；谱面光标由它推出，两侧不会不同步。
  代码区有焦点时原生选区就是这两种样子；谱面有焦点时代码区另画（`cursor.ts`）。
- **选中音符只罩音头**（升降号、唱名、八度点），不带减时线、附点、增时线与 `.jpwabc` token 里的括号（`EditDialect.noteParts`）；
  动作认音符按「选区碰到的」，所以只罩音头照样能改整个 token。**附点可单独点选**（排版器给附点标 `aug-dot`，四周放宽几像素好点中），
  选中附点按 Delete 只去附点；ABC 的附点是时值数字，没有单独符号可选。
- **歌词一次只选一段里的一个字**：展开档的音符格把各段歌词收在同一个 `<g>` 里，点选按段号（`Lyric.verse` ↔ `SyncEntry.verseNo`）取那一段自己的字；
  点亮音符时格里的歌词标 `cursor-off`、不上光标色。`.jpwabc` 的 `.Words` 逐字记原文位置（`WordsItem.source` → 模型 `Lyric.source`），所以也能单点一个字。
- **只有音符及挂在它上面的东西点了进编辑模式**；文字（歌词、页眉的标题/副标题/署名/调号拍号）点了进插入模式：
  光标落在原文里点中的那个字前后（`getExtentOfChar` 按字的中线分，画出来的字与原文按包含关系对位——署名会补「作词：」、`{三四}` 画出来不带括号），
  焦点交给代码区，接着打字就是改原文（谱面焦点下数字键是插音符，不能留在谱面上）。代码区光标停在文字里时谱面在那串字里画竖线。
- **页眉字段**：模型不记原文位置，按格式从原文认（`EditDialect.headerFields`，`visual/header.ts`：123/ABC 的 `T:`/`C:`/`K:`/`M:`，
  文本谱的 `T:`/`Z:`/`1=C4/4`…，`.jpwabc` 的 `.Title` 段），并进索引（`SyncIndex.addHeader`，条目 `header`）；
  谱面上两个排版器把页眉文字标 `hdr`、调号 `hdr-keysig`、拍号 `hdr-time`（`headerPartsOf`），文字按字对、调号拍号按角色对（`App._bindHeader`）。
- 选中色只有一种（蓝）：光标所在、点选、编辑方块、代码区选区与光标同色；拍数不对的红框要接 hover 说明，点击透过它落到音符上（`hitThroughOverlay`），
  且与上次一样时不重画（焦点一进谱面就会重画叠加层，换掉按下时点中的节点会丢掉这一下点击）。
- 动作之前先看索引是否按当前原文建的（`syncFresh`）：刚撤销、刚在代码区打过字、重排还在防抖里时先重排，否则会按旧偏移改错地方。
- token 读不懂（夹着别的东西，如文本谱 `5&rit/`）就拒绝并说明，不硬改。
- 各格式的要点：
  - **123**：`$` 结束一行曲，其后的 `w:` 只挂最后一行曲——插换行要把代码行拆开、每条 `w:` 按对位格数（`parseLyricLine` 的 `starts`）拆两半；删换行反过来接上，前一行词不够长用 `/` 补格。`+:` 续行拆不清，拒绝。
  - **ABC**：音名 ↔ 唱名按调号换算（八度口径同 `degreeFromPitch`），时值相对 `L:`，升降号是绝对的（原样保留），延音线写 `-`，换行就是代码行末（`w:` 对紧挨在前的代码行）。
  - **`.jpwabc`**：增时线与弧括号在音符 token 里；`-` 不能与 `_`、`.` 连写（`validate` 挡住）；歌词按 `@小节,音符` 锚定、小节中间的 `$` 也算新小节，所以改完按「锚住的音符在原文的位置 → 映射到新原文 → 重数坐标」重算锚点（`postEdit`，与改动并成一步撤销）。
  - **文本谱**：升降号后置、八度点按方言（番茄 `'` `,`、诗歌本 `g` `d`）；换行不是符号，增删换行 = 照现有行结构加减一刀，复用乐句重排的原文搬运重切 `Q:`/`C:` 行（`pu/phrase.ts::puLinesEdited`、`pu/relayout.ts::relayoutPuBreak`）；弧的 `)` 按队列配对，不许嵌套交叠。
- `/` 不绑定：留给歌词对位（歌词录入模式，见 [待办](../待办.md)）。
- 只在简谱两档启用；五线谱/混排不开放编辑（同统一 ScorePainter 设计的约定）。

**小节时值自检**（`model/beatcheck.ts`）：逐小节按拍号查时值（四分音符 = 1 拍，按 `divisions` 算——`<type>` 不含增时线），
混合拍（`Song.extraTimes` / 识别的 `meters`）对上任一即过；放过弱起首小节、首尾相加一小节、相邻两个不满相加一小节（反复记号劈开的）、
MusicXML 的 `implicit`；无拍号不查。编辑器标红 + 代码区波浪线；简谱识别完在核对视图按源图坐标标出（`omr/beats.ts`），
私有仓库的 `beat-check.mjs` 也经 CLI 调同一份。

## 播放

- **试听与导出 MIDI 读同一份 `App.playable()`**，由各格式共用的 `model/playsong.ts::playSourceOf` 从 `ScoreDoc` 拼：MusicXML 形状（`isXmlShaped`）走
  `playSourceOfDoc`——全部声部（mixer 的声部序号 = `Part` 序）、各 voice、和弦全部音，力度记号（pp…ff）落成 note-on 力度，
  光标只跟第一声部 voice ≤ 1；简谱形状（文本谱/123/ABC/`.jpwabc`）走 `playSourceOfSong`，展开档那份带歌词的声部当主旋律。
- **多声部按组对齐**（`model/alignparts.ts::alignPartsBySystem`，试听与导出 MusicXML 共用，对齐的是克隆）：文本谱一组不一定含全部声部，
  各声部按小节序号叠起来会错位（issue 11：只在末组出现的 `Q2` 从第一行就响）。按 `print.system` 切段、每段以小节最多的声部为参照，
  缺席或偏短的声部补无声小节（小节线、房号、跳转照抄，和弦改休止换新 id）。演唱顺序给展开档用的 `playDataOfSong` 不对齐（小节下标要对得上引擎输入）。
  **播放器回调与起播点都是 `ElementId`**：走 `PuPainter` 的原样档是 `PuPainter.highlight(id)`，其余（展开档、`.jpwabc`、单声部 123/ABC 原样档）是 `ScorePainter.highlightChord(id)`。
- 速度 = 谱面 `♩=`（`.Title` 的 `Expression` / `Q:` / MusicXML `<sound tempo>`，小节级的也认）× 工具条 ×0.5~×2。
- 两路音源：`SamplerSource`（Web Audio + smplr SoundFont）/ `NativeSource`
  （macOS `AVMIDIPlayer` + 系统 DLS GM 音源，经 Rust；支持按秒定位）。
- **谱面高亮不在 `PlaybackController` 里**——那属于「谁在画谱面」，留在 App。
- 文本谱试听必须复用排版时那份 AST。

## Tauri 外壳（`src-tauri/`，只有 2 个 `.rs`）

**不只是文件 IO 与对话框**，有三块原生能力：

| 命令 | 作用 |
|---|---|
| `export_pdf_cmd` | 各页 SVG → `svg2pdf`/`usvg` → `lopdf` 合页；载系统字体 + 随包 Bravura |
| `omr_onnx` / `omr_onnx_batch` | `ort` 跑 rec/det 模型，二进制 IPC，`mode=1` 在 Rust 侧做逐时间步 argmax。比浏览器 wasm 多线程快 ~3× |
| `midi_play_cmd` / `midi_stop_cmd` | macOS `AVMIDIPlayer`（player 必须存活，放进托管状态） |

文件 IO 与对话框用**插件**（`tauri_plugin_fs` / `dialog` / `opener`），权限在 `capabilities/default.json`。
**新增插件要同改四处**：`Cargo.toml`、`lib.rs`、capabilities、`package.json`。

Windows 桌面包的 VC++ 运行库随包内置（`src-tauri/tauri.windows.conf.json` + `scripts/win-crt.mjs`），
DLL 清单改那份 conf；来龙去脉见 [实现/OMR-简谱识别.md](../实现/OMR-简谱识别.md) 的「桌面版（Tauri）也内置 VC++ 运行库」。

## 更新检查与反馈入口（`editor/update.ts`、`editor/feedback.ts`，只在桌面版）

两者都挂在帮助对话框的第三个标签页「关于」（`editor/help.ts` 的 `buildAboutPane`），
按 `isTauriRuntime()` 判：Web 版那页只剩版本号与主页——刷新即最新，也没有邮件客户端可唤起。

- **版本号**：只在 `package.json` 维护一处，`vite.config.ts` 的 `define` 注入成 `__APP_VERSION__`；
  `release.sh` 把它同步到 `tauri.conf.json` / `Cargo.toml` / `index.html` 的 JSON-LD。前端别再抄常量。
- **更新检查是「只查不装」**：查 GitHub Releases API 比版本号，有新版问一句，确定就用 `opener` 打开
  release 页由用户自己装。**没上 `tauri-plugin-updater`**——那条路要生成并保管签名密钥、改
  `.github/workflows/build.yml` 注入 `TAURI_SIGNING_PRIVATE_KEY` 并产出 `latest.json`（动 workflow），
  而存量用户照样得手动装一次新版才享受得到。要换只换 `update.ts`。
- **节流判据**（独立 key `jpeditor-update-state`，不进 `PersistedSettings`——那份是
  `App.saveSettings()` 整对象覆盖写的，从别处补字段会被抹掉）：启动后延迟 8 秒查一次，
  距上次检查不足 24h 不查，同一个新版本只提示一次，用户可在关于页关掉自动检查。
  查询失败（断网 / 限流）一律静默返回，不弹错误框。
- **反馈走 `mailto:`**：预填收件人、带版本号的主题与一段可删的环境信息；不自建上报服务——
  这个应用全程本地运行，不该为一条反馈开网络通道。唤不起邮件客户端时在关于页显示邮箱明文兜底。
- `opener` 的 `open-url` 默认 scope 为空，`capabilities/default.json` 里显式放行了
  `https://github.com/*`、主页与 `mailto:*`——**换仓库 / 换邮箱要同改那里**，否则点了没反应。

## 关键判据

- 点选高亮走 **CSS 类、不重渲染**。
- 双指缩放在 `main.ts`（ctrl+wheel / WebKit `gesture*`），按页内归一化坐标锚定；
  `--score-zoom` 设在 `#score-pane` 上，**整条 calc 不能挪到 `:root`**。
- `.jpwabc` 读时 BOM 探测、存 UTF-16LE + BOM（兼容 JP-Word）。
- 能打开哪些扩展名**只在 `src/common/filetypes.ts` 写一次**。
- `window.__app` 运行时暴露，供脚本化测试。
