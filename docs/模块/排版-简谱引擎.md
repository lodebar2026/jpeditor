# 排版：简谱引擎

**判据全录** → [../实现/简谱纵向栅格.md](../实现/简谱纵向栅格.md)（447 行）、[../实现/乐句排版.md](../实现/乐句排版.md)、[../实现/歌词标点挤压.md](../实现/歌词标点挤压.md)

## 职责

引擎输入 → 页面树 → SVG。含横向排布、纵向栅格、符杠、弧线、上方带堆叠、断行分页、乐句断句。
输入是 `ScoreDoc` 的只读投影（`layout/input.ts`），引擎只读不写：符杠分组、段落词挪位这类排版中间态都记在 `Line` 上。

## 吃什么吐什么

```
ScoreDoc → jianpuinput（JScore）+ LayoutOptions → Layout/Line → PageItem 树 → renderPageSvg → SVGSVGElement
                                                  └→ walkPageItem → DrawList / PPTX 形状
```

## 关键判据

- **判据是谱面**：改引擎输入（投影分支、断点写回）必跑 `jianpu-svg-dump --diff`，各格式逐页 SVG 指纹不许变，
  变了逐份定性。三个分支的观感差异（`.jpwabc` 小节线不画样式与反复、MusicXML 只取第一声部最高音、简谱形状不画和弦）
  **不在输入这一层抹平**。
- 引擎按拍位稳定排序小节条目（不改输入）；换行条目的 `position` 要落在小节末 / 断点和弦的止点，
  否则排序会把它挤到第一个和弦之后（001《圣哉，圣哉，圣哉》行尾的「宰！」被甩到下一行）。
- **一把尺子**：上方那一带用 `jpStackGap`（1/6 em，要给弧留手）；
  **数字 ↓ 减时线 ↓ 低音点**这条向下的阶梯走 `jpBelowGap`（1/9 em），三档墨迹净距相等。
- 八度点、附点、反复点一律**矢量圆**；附点圆心与数字墨迹中心等高。
- 拍号**竖向只认拍值字号**（`TIME_SIG_GAP_EM` = 1/9 em，墨迹到墨迹、上下对称）；
  分数线长度按位数算。原先那两个「基线 ÷ H」常量换个字号就挤成一团。
- **不能用 `<text>.getBBox()` 核对数值**：SVG 对 `<text>` 返回的是**行框**不是墨迹。
- 标题块挂进排好的页要**另包一层 Group**——`Group.update` 会把子元素归一化到原点、
  偏移收进 group 自身的 x/y，直接 `add` 再设 `y` 会让标题压到谱面上。
- 转拍号前后各留 `numberSize/4`，前面那格走 `Entry.leadSpace`——**不能靠平移图元**。
- 乐句排版：行长以**小节数**计（目标 4、下限 3、上限 7），但「放不放得下」由
  `App._phraseFit` 量出的**真实坐标**判。**别拿 `targetMeas` 去顶行长目标逼它并行**——
  目标是连续量，逼不出「整句」这种离散结构（350 会断在句子中间）。
- 成书/展开档/混排各有自己的纵向范围（`jpStaffTop/Bottom`、`barlineHeight`、`mixStaffHeight`）——
  那是**量出来的**，不是画法。
- **与原 Kotlin 近乎逐行翻译**：`layout.kt→layout/layout.ts`、`draw.kt→layout/painter.ts`、`skia.kt→common/geom.ts`，
  改行为前先看 `../src/main/kotlin/` 对应文件确认原意。Skija 值类型不可变（offset/inset/union 返回新对象），TS 端保持同样语义。

## 已知限制

- **跨行 slur/tie 被静默丢弃**：`addTie`/`addSlur` 里 `chordEntry.get(endCh)` 取不到就 `continue`，
  而 `chordEntry` 只认本行（重构路线 R5）
- `.musicxml` 展开档不画小节线（投影的行里没有普通小节线元素，见 [../待办.md](../待办.md) §1.1）
- `layout.ts` 已按 R4 切成 `options ← pageitem ← entry ← layout` 单向四份；仍留一处真环 `pageitem ⇄ jpglyph`（`JpOctaveDot` 构造器调 `jpDot`），两边顶层只有声明，安全
- 窄纸上「光歌词就比版心宽」的行会微叠（`placeColumns` 按比例打折守版心）
