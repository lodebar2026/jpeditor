## 1. 五格式原生编辑的剩余

`.pu` / `.jpwabc` / `.123` / `.abc` / `.musicxml` 五种格式**已经都能原生打开、编辑、存回原格式**，
文本与谱面也已双向光标/选择同步。**做过什么、各自的验数在 [进度.md](进度.md)**；
判据与结构在 [模块/模型-scoredoc.md](模块/模型-scoredoc.md)、
[模块/编辑器与播放.md](模块/编辑器与播放.md)、[模块/源格式-abc家族.md](模块/源格式-abc家族.md)。

这一节只留**还没做的两件**。它们是一件事的两半，**要一起翻**：

### 1.1 让排版直接吃 `ScoreDoc`，拆掉 `model/topu.ts`

现在 `.123` 与 `.abc` 的排版是借 `topu.ts` 转成 `PuDoc` 走文本谱那条路
（适配器的 `FormatCaps.viaPuDoc` 标着这座桥）。要让 `PuPainter` / `toxml` / `toscore`
直接吃 `ScoreDoc`——即 §3 重构路线的 **R2 后续**，`src/pu/` 6890 行。

做完的连带好处：`FormatCaps.viaPuDoc` 这一位消失；`.jpwabc` 的双向定位粒度从「等它改吃
`ScoreDoc`」升到 `element`。

**验**：`pu-parse-check.mjs` / `xml-roundtrip.mjs` / `xml-direct-check.mjs` /
`page-check.mjs` / `sync-check.mjs` 零回退。

### 1.2 `.musicxml` 的保存从 patch 翻成全量重写

`ScoreDoc ↔ MusicXML` 直通已经就位并验过（568 份重写后十类关键元素一个没掉），
但保存**仍走 `patchMusicXml`**。原因不是直通不行，而是**编辑链路还不是 `ScoreDoc` 原生的**：
编辑器里编的是简谱转换文本，保存时手上的模型是「`jpwabc` 文本 → `Score`」，
而 `Score` 装不下和弦——走「Score → ScoreDoc → 全量重写」会把底本里的 12646 个和弦洗掉，
反不如 patch 把改动并回原文。

所以这一条的前置是 §1.1。前置做完之后，翻转只是改一行取模型的地方
（`export.ts::buildMusicXml` 改成从 `ScoreDoc` 取），`musicxmlpatch.ts` 随之降为兜底。

**验**：`xml-direct-check.mjs` 与 `omr-export-check.mjs` 零回退；
`xml-roundtrip.mjs` 的 patch 那一组改为兜底路径的回归。

### 1.3 两条已知的表达限制（不挡上面两件）

- `.musicxml` 的双向定位**只到小节级**：DOMParser 不给字符偏移。要 element 级得换带偏移的
  SAX 解析。用户已明确 XML 不需要文本编辑特性，收益低，先不做。
- 123 那一档的**拉丁歌词**仍是连写（`AbcFamilyEmitter.lyricSeparator` 为空串）。
  中文语料碰不到；要改得连 `parseLyricLine` 一起看，否则往返会多出音节。

## 2. 123 语料迁移的剩余

### 2.1 残留的往返不幂等（0.15%）

跑 `PU_CORPUS=… HYMN500=… node scripts/j123-migrate.mjs` 看 `testdata/j123-coverage.md`。
已知模式（每类 1–2 份）：

| 现象 | 样本 |
|---|---|
| `$` 与小节线顺序 | `赞美诗增订本/0101_十字架` |
| 多连音起点与 `$` 相邻时错位 | `赞美诗增订本/0133_耶稣升天` |
| 歌词末尾标点归属 | `赞美诗歌1300/0632_活出生命的色彩` |
| `I:space` 指令值被吞 | `教会诗声/0149_主耶稣在世七步路` |

**验**：全量迁移后 `往返不幂等` 计数下降，且既有的 568/568（500 首两路）不回退。

### 2.2 残留的「无法表达」（0.14%）

| 项 | 份数 | 样本 |
|---|---:|---|
| 文字行 `W:` | 9 | `个人上传/8669_我从前风闻有你` |
| 圆滑线 | 5 | `选本诗歌附录版/0091_我的主我心爱祢` |
| 多段歌词 | 5 | `赞美诗增订本/0005_你是我的主` |
| 多声部 | 3 | `赞美诗歌(友谊)/0243_永生的路` |
| 分曲 `-----` | 2 | `赞美诗选编1050/0005_你们要赞美耶和华` |
| 房号 | 1 | `赞美诗歌(友谊)/0547_看哪！新郎来到` |

**每条都要先判是哪一类**：123 规范表达不了（改规范）、转换层漏了（改代码）、
还是上游解析器没读进来（见 §4，不是 123 的账）。报表已经会区分后者，但这 25 份还没逐个看过。
（印刷段号 4 份、倚音 2 份已随 `frompu.ts` 无损化消掉：段号原来只挂首音节、首音节为空就丢；倚音原来丢了升降号与时值。）

### 2.3 书级：`book.toml` 与 `book.jpcss`

[格式/123格式.md](格式/123格式.md) 定了 500 首的存储布局（一首一文件 + 书清单 + 书级样式表），
但 `book.toml` 的字段与 `book.jpcss` 的语法都还没落地。前者要能表达曲号→文件、分类、目录、
索引、扉页、装箱规则；后者见 [样式机制.md](样式机制.md)。

**验**：用它重跑 `scripts/rebuild.mjs` 的整本排版，`line-check.mjs` 全书基线零回退。
