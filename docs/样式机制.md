# 样式机制（设计稿）

> 诗歌本排版要的「类 CSS 样式定制」。现状是**三套互不相通的尺子**，本文给收敛方案。
> 现有实现见 [模块/样式与设置.md](模块/样式与设置.md)；格式侧的引用点见 [格式/123格式.md](格式/123格式.md) §10。

## 1. 现状：三套尺子

| 尺子 | 位置 | 从哪来 | 服务 |
|---|---|---|---|
| `LayoutOptions`（约 140 项） | `src/layout/layout.ts` | 手调 + 从 2019 年成品 .pptx 量回来 | `.jpwabc` 原样档、展开档 |
| `PuMetrics` | `src/pu/metrics.ts` | 对原版渲染逐项实测 | 文本谱原样档 |
| `BookStyle` | `src/pdflayout/bookstyle.ts` | `stats.ts` 从原书统计**中位数** | 成书 PDF |

`metrics.ts` 开头明写「与 `jpStackGap` 那套**不是同一把尺子**，混用只会两头不像」——
这不是疏漏，是各自有实测来源。问题在于**没有上层把它们统一描述**，于是：
换一处字号要改三个地方；诗歌本样式定制没有入口；主题（印刷/投影/校对）无法整套切换。

## 2. `BookStyle` 已经是类 CSS 的一半

| CSS 概念 | `bookstyle.ts` 已有的对应物 |
|---|---|
| 选择器 | `StyleRole` 20 个角色：`title` `songNumber` `category` `credit` `keyMeter` `note` `tuplet` `verseNum` `chord` `lyric` `lyric2` `sectionWord` `story` `toc` `tocHeading` `tocSub` `frontTitle` `header` `footer` `smufl` |
| 声明块 | `RoleStyle { font, size, baselineAdjust, align, color }` |
| `font-family` 间接层 | `fonts: Record<string, FontRef>`，`FontRef { family, mode:"font"\|"path", file, face, bold }`——同一 face 只嵌一次子集 |
| 相对单位 | **em**（基准 = 音符字高 `roles.note.size`），不随字号变的量存 pt |
| 级联/继承 | `mergeBookStyle()` 深合并（数组整体替换） |
| 校验 | `validateBookStyle()` 查缺角色与悬空字体引用 |
| UA 默认样式 | `defaultBookStyle()` / `roleFontDefaults()` |
| `@page` 对开 | `pageMargins()` 按页奇偶镜像 |
| 外置样式表 | `testdata/500/bookstyle.json`，`scripts/rebuild.mjs --style` 载入 |

**缺的只有两样：选择器的上下文限定，和一条明确的级联链。** 而且它只服务成书 PDF。

## 3. 设计

### 3.1 选择器

```
note                     角色
lyric[verse=2]           限定：第 2 段歌词
note[mode=expanded]      限定：展开档
@page:left / :right / :first    页位（对开镜像、首页）
@theme projection        命名主题
```

**不做 CSS 全量选择器**：歌谱没有 DOM 树，不存在后代/兄弟关系，角色 + 少量限定已经够用。
限定维度只开三类：**档位**（expanded/original/staff/mixed）、**页位**、**段号**。

### 3.2 级联（后者覆盖前者）

```
内置默认 defaultBookStyle()
  → 命名主题（印刷歌本 / 16:9 投影 / 校对对照）
    → 书样式表 book.jpcss
      → 曲内局部覆盖（123 的 I:style / [I:style …]；文本谱的 FontSize:/Margin:）
        → 用户面板（运行时，localStorage 持久化）
```

合并语义沿用 `mergeBookStyle`：对象深合并、数组整体替换。每层都是 `DeepPartial<StyleSheet>`。

### 3.3 单位

沿用现约定，**不要改**：

- 随字号缩放的量存 **em**，基准是音符字高 → 换字号时版式自动跟随
- 线宽、点直径、纸张尺寸、页边距存 **pt**
- 文档内的百分比（文本谱 `FontSize: t2=65%`）归一成 em 或倍率后进级联

### 3.4 收敛路径（三套尺子 → 一套 + 三个适配器）

```
        StyleSheet（唯一真相，级联后得到 computed style）
                 │
    ┌────────────┼────────────┐
    ▼            ▼            ▼
LayoutOptions  PuMetrics   BookStyle
（适配器）      （适配器）    （适配器）
```

- 两个适配器的**原型已经存在**：`pdflayout/browser.ts::applyBookStyle`、`layout/pptxstyle.ts::applyPptxStyle`。
  契约也已立好：**painter 构造之后、`resize` 之前调**。
- `PuMetrics` 那一路多一步：它整套尺寸是实测来的、不由一个基础字号派生，
  所以面板给的 pt 要经 `PuPainter.resolveScale` 换成**整体缩放**（分母由 `digitFontSizeOf` 从 `digitInkHeight` 反推）。
  这层换算保留，只是输入改为从 `StyleSheet` 取。
- 文本谱已解析但未实现语义的 `Space:` / `Off:` 接为曲内覆盖。

### 3.5 主题

三套命名主题，切主题 = 换一整层级联：

| 主题 | 纸 | 特征 |
|---|---|---|
| 印刷歌本 | A4/A5 实际尺寸 | 多段歌词叠排、反复不展开、对开镜像页边距、目录页眉页码 |
| 16:9 投影 | `PAGE_RATIOS` | 逐遍展开一屏一段、大字号、独立标题页、页脚曲名 + 页码 |
| 校对对照 | 随原件 | 按源图/原件坐标定位，叠加半透明识别层 |

## 4. 风险与回归

样式层一动就会牵动全书版面，**必须拿既有几何基线把关，零回退才算过**：

| 脚本 | 把关什么 |
|---|---|
| `node scripts/pptx-ref-check.mjs` | 拆开导出的 .pptx 量几何，与 2019 年成品 ppt500 同一套判据 |
| `node scripts/page-check.mjs` | 分页版面（越纸 / 谱行相压 / 压页脚 / 行内歌词相压 / 展开档结构） |
| `node scripts/line-check.mjs` | 成书断句 D1~D10 + 版面 V1~V13 + 全书基线 |
| `node scripts/pptx-check.mjs` | 原样/展开两档版面 |
| `node scripts/zoom-check.mjs` | 四档纸张宽度一致 + 缩放 |

另记两条既有告诫：

- `browser.ts` 里有几个**手调常量**，而 `bookstyle.json` 是 `stats.ts` 实测产物——
  默认值必须写在代码里，否则重跑生成脚本就丢。
- 「改这几个常量会牵动全书断句」（弧高 → 行高 → 每页行数 → 重排），动完必跑 `rebuild.mjs` + `line-check.mjs`。
