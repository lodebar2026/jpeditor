# 样式机制

> 诗歌本排版要的「类 CSS 样式定制」。入口在 `src/style/`；模块页见 [模块/样式与设置.md](模块/样式与设置.md)，
> 格式侧的引用点见 [格式/123格式.md](格式/123格式.md) §10，歌本样式表的文本语法见 [格式/jpcss.md](格式/jpcss.md)。

## 0. 三层：数据 → 模板 → 样式

| 层 | 管什么 | 在哪 | 状态 |
|---|---|---|---|
| **数据** | 这首歌有哪些信息：标题、词曲、版权，外加扩展 meta（英文标题、经文、标签、分类…） | `Song.work` / `identification` / `pageText` + `Song.meta`（map，键注册表 `model/metakeys.ts`） | 设计稿（§9） |
| **模板** | 哪个字段排进哪个区域的哪个槽位、按什么格式印、怎么装页 | `StyleSheet.template`，文本写在歌本 `.jpcss` 的 `@template`/`@flow` | 设计稿（§10） |
| **样式** | 角色的字体、字号、颜色、对齐；各尺子的 preset/overrides。**只管全书统一的版式，不改谱面内容、不做逐曲规则**（§11） | `StyleSheet.roles` 等（§2） | 已落地 |

**一本歌本 = 一份 `.jpcss`（模板 + 样式）+ 一份书清单 `book.json`（曲目与逐曲 meta 覆盖）**。
内置 `pu-original`（文本谱原样档）；歌本样式 `hymn500`（500 首成书，基准是现有重排结果）与 `kl2020`（声合为一混排歌本，
基准是 KL2020 单曲版/1219 版 PDF）照印刷本逐点量出，**不在本仓库**。

## 1. 分层：一份样式表 + 四个适配器

```
内置主题（themes.ts）→ 书样式表 / 用户层 ──computeStyle(上下文)──→ StyleSheet
                                                                    │
                   ┌─────────────────┬──────────────────┬───────────┴──────┐
                   ▼                 ▼                  ▼                  ▼
            LayoutOptions        PuMetrics          BookStyle         MixedOptions
          style/jianpu.ts      style/pu.ts        style/book.ts      style/staff.ts
        原样档 / 展开档 / 成书   文本谱原样档          成书               五线谱 / 混排
```

四把尺子**不合并**：`LayoutOptions` 从 2019 年成品 .pptx 量回、`PuMetrics` 对原版渲染逐项实测、
`BookStyle` 由 `stats.ts` 统计原书中位数、`MixedOptions` 照搬 musicpp 的 Engraver 常量——各有实测来源，
`metrics.ts` 开头明写「与 `jpStackGap` 那套**不是同一把尺子**，混用只会两头不像」。
样式层做的是**统一入口**：换字号、换纸、换配色都只写样式表，由适配器按各自口径落值。

## 2. 样式表（`sheet.ts`）

| CSS 概念 | 对应物 |
|---|---|
| 选择器 | `StyleRole` 20 个角色（`note` `lyric` `title` `credit` `chord` …），外加规则的上下文限定（§3） |
| 声明块 | `RoleDecl { size, color, font, family, weight, features }`（对齐由槽位定，不写在角色上）；`page { paper, w, h, ink, background }` |
| 内容扩展 | `jianpu { preset, overrides }`（简谱内容）、`staff { preset, overrides }`（五线谱内容），键是 `keys.ts` 的 kebab-case 逻辑键；`book`（整份 `BookStyle`） |
| 继承 | `mergeStyle()` 深合并（数组整体替换） |
| UA 默认 | 各尺子自己的构造默认值（`LayoutOptions` 的 `0 = 引擎自算` 等），样式表不重复写 |

**块按谱面内容分，排版器由模式决定**：`@jianpu` 在纯简谱档落 `LayoutOptions`、在混排落 `MixedOptions` 的简谱层；
`@staff` 落 `MixedOptions`。内部字段名不外露，对照表是 `style/keys.ts`（`JIANPU_KEYS` / `STAFF_KEYS`）。
**字体走角色**：`note` / `lyric` / `smufl` / `chord` 的 `font` / `family` / `weight` 由 `keys.ts::ROLE_FONTS`
落到各排版器自带的字体字段，解析在 `style/fonts.ts`。混排谱表上缩小的那支简谱字（`mixFont`）是派生 getter，不单独设。

**成书没有 json**：`BookStyle` 是内存里的中间对象，由歌本样式表算出（`style/bookjpcss.ts::bookStyleOf`，
反方向 `printBookJpcss` 供统计脚本生成实测部分）。纸、字体、角色、间距（`@jianpu` 的 `book` 一列）、断句（`@break`）、
起排位置（`@flow`）、目录几何（`@template toc`）全在样式表里，数值原样进出、不补默认值，重排结果逐字节不变。
对照表见 [格式/jpcss.md](格式/jpcss.md) §10。

**实测常量不搬进样式表**：主题只选 `preset`，公式留在适配器里，之后再叠逐字段 `overrides`。
常量改存比例会出浮点尾差（`em/20` 与 `em*0.05` 在 28 上差一个 ulp），几何基线就破了。

## 3. 级联（`cascade.ts`）

```
内置主题（themes.ts）
  → 歌本样式表（歌本 .jpcss；成书是「实测部分 + 模板」两份，`BookStyle` 由它算出，见 style/bookjpcss.ts）
    → 曲内局部覆盖（文本谱 FontSize:/Margin:；MusicXML 的 <scaling>/<defaults>；谱里的纸：`style/paper.ts::docPageLayer`）
      → 用户层（编辑器面板，localStorage）
```

- 一层是 `StyleRule[]`，规则 = `{ when?, set }`；`computeStyle(layers, ctx)` 按层序、层内按规则序叠。
- 上下文限定五个维度：**档位** `mode`（expanded/original/staff/mixed）、**引擎** `engine`（jianpu/pu/book/staff）、
  **分页** `paged`（true = 有实际纸张，false = 长图）、**页位** `page`（left/right/first）、**段号** `verse`。
  后两个只实现了匹配，还没有消费者。
- `paged` 取决于纸，而纸本身是样式表算出来的：调用方一律用 `themes.ts::computeStyleForPaper`（先算一趟看纸，
  再带上 `paged` 算第二趟）；`jianpu.ts::isLongImage` 与它共用 `isPagedSheet` 一处判据。
- 引擎这一维是因为面板本来就分开记 `.jpwabc` 与文本谱原样档的纸与字号（两把尺子口径不同）。
- **曲内覆盖不走深合并**：文本谱的 `FontSize: all=80%` 是乘法，仍由 `layout/original/metrics.ts::applyDocOptions` 叠在方言版式之上；
  MusicXML 的版面单位由 `mixed/layout.ts` 读，优先于主题。
- 用户层写入走 `upsertRule`：限定完全相同的规则就地合并，层不会越改越长。

## 4. 单位（`units.ts`）

样式值是 `Length`：裸数字按 pt，或带单位的字符串。本轮支持三种：

| 单位 | 定义 |
|---|---|
| `pt` | 绝对长度 |
| `em` | 所在角色的字号（CSS 语义）；不属于角色的度量量取 `note` 的字号。`note.size` 本身只收 pt |
| `sp` | 线距 = **名义谱高** / 4 |

**名义谱高**是五线谱与简谱共用的基准：五线谱 = 五条线的跨度（= SMuFL 字号，40 tenths），
简谱 = 默认小节线的上下缘跨度（4/3 字号；混排简谱层 `mixStaffHeight` 30 配数字字号 30 之于 40，同比 0.75）。
它是**名义值**：实际画出的小节线高（成书 1.66 墨迹高、文本谱 29/34k、`jpStaffTopOverride`）另行覆写，不牵动 sp。

- 换算只在适配器里做（`resolveLength`），引擎只见数字；裸数字原样返回，内置主题逐位不变。
- 五线谱的 overrides 只收 em / sp：pt 要等 `<scaling>` 读进来才知道折多少 tenths。
- **样式里的尺寸值一律是字号口径，不收墨迹高**。原书/原版量到的是墨迹高，只在产生样式值时换算一次：
  成书由 `gen-bookstyle.mjs` 按各角色样本字（`bookstyle.ts::INK_SAMPLE`）在字体文件里量「墨迹高 ÷ 字号」，
  角色 `size` 存字号、`*Em` 以音符字号为基准；文本谱的 `digitSize` 是数字字号，
  `digitInkHeight` 只是 painter 定稿时按字体实测推出的内部单位（`metrics.ts::withDigitInk`），不是样式值。
  代价：换了字体（跨平台回退）墨迹大小会跟着字体走，不再强行等高。

## 5. 主题（`themes.ts`）

| 主题 | 谁在用 | 内容 |
|---|---|---|
| `projection`（16:9 投影） | 编辑器展开档（两种格式）、导出 PPTX | 字号 28/48/36、960×540、`jianpu.preset: "pptx"` |
| `print`（印刷歌本） | 编辑器原样档（`.jpwabc` 与文本谱） | 纸「长图」、`.jpwabc` 字号 28（文本谱不给 = 跟随版式）、`preset: "original"` |
| `book`（成书） | `scripts/rebuild.mjs` | `preset: "book"`，其余在 `book` 块（由歌本样式表算出的 `BookStyle`） |
| `staff` | 五线谱 / 混排 | 纸 A4（谱里没写 `<page-layout>` 时用；用户层单记一套，不借原样档的纸）、`preset: "musicpp"` |

编辑器里**主题由排版模式决定**（展开 → projection、原样 → print），切模式按钮就是整层切换；
每个主题一层用户规则，设置面板的「恢复本档默认」清的就是当前那一层。

## 6. 适配器的判据

- 契约沿用：**painter 构造之后、`resize` 之前调**；简谱构造字号取 `jianpuFontSize(sheet)`。
- 简谱原样档不单独设标题/词曲字号，缺省按出厂比例 48/28、36/28 取整派生（`jianpuSizes`）。
- 文本谱的字号面板给的是 pt，但它整套尺寸不由一个基础字号派生：`style/pu.ts` 只给出 `digitFontSize`，
  由 `layout/original/compose.ts::resolveScale` 换成**整体缩放**（分母是版式含谱面指令时的 `digitSize`）。
  叠放顺序：`metricsFor(方言)` → `applyDocOptions` → 面板那层。**没有逐字段覆盖层**（`@pu` 已删：原样档照原版实测）。
- 五线谱适配器**先落角色字体再取 em**：`em` 就是 `musicFont` 的字号，换了字号基准跟着变。裸数字是 tenths 原样落值。
- 成书的角色字号直接用，不再在消费端反算。原先按墨迹高调的比例常量已折成字号口径（Times 数字墨迹 ≈ 0.674 字号、宋体汉字 ≈ 0.89）：
  弧高 `slur-arc/max/min`、调号拍号的升降号抬升与分数线（`bookparts.ts::keyMeterItems`）、页脚留白 1.1 个页脚字号、
  注解行距比例（库里的注解 `size` 是墨迹高，`rebuild.mjs` 先折成字号再比）。
- `style/book.ts::applyBookPreset` 里有几个**手调常量**，而歌本样式表的实测部分（`<id>-measured.jpcss`）是 `stats.ts` 生成的——默认值必须写在代码里（`bookstyle.ts::defaultBookStyle`），否则重跑生成脚本就丢。
- 「改这几个常量会牵动全书断句」（弧高 → 行高 → 每页行数 → 重排），动完必跑 `rebuild.mjs` + `line-check.mjs`。

## 9. 数据：`Song.meta`（设计稿）

- 形状 `Record<string, string[]>`：单值是一项，多行、多标签是多项。**扩一个数据项只在注册表加一行**，模型类型、解析器接口、清单格式都不用改。
- 注册表 `MetaKeyDef { key, label, role?, split?, i123?, xml?, db? }`：给出默认角色、录入时的切分规则、各格式里的名字。
  不在表里的键照样保存、往返，模板里也能用 `{meta.xxx}` 引用。
- 首批键：`title-alt` `epigraph` `epigraph-ref` `scripture-refs` `tags` `category` `tune` `ccli` `rights-extra`
  `note-bl/bc/br` `layout.new-page` `layout.melody-only`。
- 排版器要计算的字段（标题、词曲、调号拍号）**仍然强类型、不进 map**。
- 通用往返：MusicXML 用 `<miscellaneous-field name="键">`；123 用 `I:meta 键 值`。
- **文本谱不做语义猜测**：`TL/TR` 在语料里既当分类也当词曲用，按槽位原样放在 `pageText`，由模板按位置排出。
- 书清单里的 `meta` 按键浅覆盖谱文件里的值。

## 10. 模板

- 区域：`song-head` `song-foot` `page-header` `page-footer` `toc`，由排版器在固定时机调用。
- `flow: fixed` 按页内绝对基线定位，500 首的标题块走这种；`flow: block` 占高度、把谱面往下推，KL2020 与文本谱页脚走这种。
- 行有五个槽位：`left center right inner outer`，`inner`/`outer` 按页码奇偶换边。内容是字符串插值加过滤器，
  外加组件（`key-meter()` 等）。**空值折叠**：字段全空的行不输出、不占高。
- 装页 `@flow`：`song-start: new-page | continue`。KL2020 单曲版用 new-page，1219 版用 continue、再按本曲
  `layout.new-page` 决定；500 首的半页起排由 `rebuild.mjs` 实现，`@flow` 只给它几个起排位置（`first-system-top` 等）。
- **实测基线直接写数**：500 首标题块、页眉页码的基线写成 `row(baseline: 78.63)`（`ref()` 已删）。文本 ↔ double 按最短往返，
  几何仍逐位一致；重跑统计后按报告里的「模板基线实测」核对。文本谱那一路的落位由调用方经 `dy` 给。
- 实现：`style/jpcss.ts`（手写解析、`行:列` 报错、`printJpcss` 往返）、`style/template.ts`
  （`layoutRegion(region, ctx, measure)`，纯函数，文字测量由调用方注入）、过滤器与组件各一张注册表。

## 11. 逐曲修改走数据，不走样式表

- **样式表只管全书统一的版式**。谱面内容（小音符、段号改写、符干、文字换行、和弦上方音画小）和逐曲的位置微调、
  某段歌词换字体，都先用脚本改好数据，排版器照数据排。`.jpcss` 里写 `@song` 或 `角色[…]` 解析时报错。
- 数据用 MusicXML 的标准写法表达：`<cue/>`、`<type size="cue">`、`<stem>`、`<lyric><text>` 原文与 `font-family/font-size`、
  `<words>` 文字里的换行、`<harmony|words|segno relative-x>`、`<words|lyric relative-y>`。混排读这些属性（`mixed/layout.ts`、`layoutpass.ts`）。
- XML 表达不了的排版开关放书清单 `meta`：`layout.chinese-hyphen`（歌词连字符用「—」）、`layout.melody-only`、`layout.new-page`。
- KL2020：`scripts/kl2020-prep.mjs` 把原排版程序 `fixPaoScore` 的逐曲修改按小节、拍位、声部定点写进 `.fixed.xml`（原文件不动），
  每条补丁报命中数、命中 0 报错；清单 `file` 指向副本。
