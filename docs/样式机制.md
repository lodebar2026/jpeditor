# 样式机制

> 诗歌本排版要的「类 CSS 样式定制」。入口在 `src/style/`；模块页见 [模块/样式与设置.md](模块/样式与设置.md)，
> 格式侧的引用点见 [格式/123格式.md](格式/123格式.md) §10。

## 1. 分层：一份样式表 + 四个适配器

```
内置主题（themes.ts）→ 书样式表 / 用户层 ──computeStyle(上下文)──→ StyleSheet
                                                                    │
                   ┌─────────────────┬──────────────────┬───────────┴──────┐
                   ▼                 ▼                  ▼                  ▼
            LayoutOptions        PuMetrics          BookStyle         MixedOptions
          style/jianpu.ts      style/pu.ts        style/book.ts      style/staff.ts
        原样档 / 展开档 / 成书   文本谱原样档          成书               五线谱 / 混排
```

四把尺子**不合并**：`LayoutOptions` 从 2019 年成品 .pptx 量回、`PuMetrics` 对原版渲染逐项实测、
`BookStyle` 由 `stats.ts` 统计原书中位数、`MixedOptions` 照搬 musicpp 的 Engraver 常量——各有实测来源，
`metrics.ts` 开头明写「与 `jpStackGap` 那套**不是同一把尺子**，混用只会两头不像」。
样式层做的是**统一入口**：换字号、换纸、换配色都只写样式表，由适配器按各自口径落值。

## 2. 样式表（`sheet.ts`）

| CSS 概念 | 对应物 |
|---|---|
| 选择器 | `StyleRole` 20 个角色（`note` `lyric` `title` `credit` `chord` …），外加规则的上下文限定（§3） |
| 声明块 | `RoleDecl { size, color }`；`page { paper, w, h, ink, background }` |
| 引擎扩展 | `jianpu { preset, overrides }`、`pu { overrides }`、`staff { preset, overrides }`、`book`（整份 `BookStyle`） |
| 继承 | `mergeStyle()` 深合并（数组整体替换） |
| UA 默认 | 各尺子自己的构造默认值（`LayoutOptions` 的 `0 = 引擎自算` 等），样式表不重复写 |

**实测常量不搬进样式表**：主题只选 `preset`，公式留在适配器里，之后再叠逐字段 `overrides`。
常量改存比例会出浮点尾差（`em/20` 与 `em*0.05` 在 28 上差一个 ulp），几何基线就破了。

## 3. 级联（`cascade.ts`）

```
内置主题（themes.ts）
  → 书样式表（成书：bookstyle.json 作为 `book` 块）
    → 曲内局部覆盖（文本谱 FontSize:/Margin:；MusicXML 的 <scaling>/<defaults>）
      → 用户层（编辑器面板，localStorage）
```

- 一层是 `StyleRule[]`，规则 = `{ when?, set }`；`computeStyle(layers, ctx)` 按层序、层内按规则序叠。
- 上下文限定四个维度：**档位** `mode`（expanded/original/staff/mixed）、**引擎** `engine`（jianpu/pu/book/staff）、
  **页位** `page`（left/right/first）、**段号** `verse`。后两个只实现了匹配，还没有消费者。
- 引擎这一维是因为面板本来就分开记 `.jpwabc` 与文本谱原样档的纸与字号（两把尺子口径不同）。
- **曲内覆盖不走深合并**：文本谱的 `FontSize: all=80%` 是乘法，仍由 `pu/metrics.ts::applyDocOptions` 叠在 `pu.overrides` 之后；
  MusicXML 的版面单位由 `mixed/layout.ts` 读，优先于主题。
- 用户层写入走 `upsertRule`：限定完全相同的规则就地合并，层不会越改越长。

## 4. 单位（`units.ts`）

样式值是 `Length`：裸数字按 pt，或带单位的字符串。本轮支持三种：

| 单位 | 定义 |
|---|---|
| `pt` | 绝对长度 |
| `em` | 所在角色的字号（CSS 语义）；不属于角色的度量量取 `note` 的字号。`note.size` 本身只收 pt |
| `sp` | 线距 = **名义谱高** / 4 |

**名义谱高**是五线谱与简谱共用的基准：五线谱 = 五条线的跨度（= SMuFL 字号，40 tenths），
简谱 = 默认小节线的上下缘跨度（4/3 字号；混排简谱层 `mixStaffHeight` 30 配数字字号 30 之于 40，同比 0.75）。
它是**名义值**：实际画出的小节线高（成书 1.66 墨迹高、文本谱 29/34k、`jpStaffTopOverride`）另行覆写，不牵动 sp。

- 换算只在适配器里做（`resolveLength`），引擎只见数字；裸数字原样返回，内置主题逐位不变。
- 五线谱的 overrides 只收 em / sp：pt 要等 `<scaling>` 读进来才知道折多少 tenths。
- 墨迹口径不开放成可写单位：成书 `BookStyle.metrics.*Em` 的基准是原书量到的音符**墨迹高**，留在 `book` 块内原样用；
  文本谱的缩放基准 `digitInkHeight` 同理。

## 5. 主题（`themes.ts`）

| 主题 | 谁在用 | 内容 |
|---|---|---|
| `projection`（16:9 投影） | 编辑器展开档（两种格式）、导出 PPTX | 字号 28/48/36、960×540、`jianpu.preset: "pptx"` |
| `print`（印刷歌本） | 编辑器原样档（`.jpwabc` 与文本谱） | 纸「长图」、`.jpwabc` 字号 28（文本谱不给 = 跟随版式）、`preset: "original"` |
| `book`（成书） | `scripts/rebuild.mjs` | `preset: "book"`，其余在 `book` 块（bookstyle.json） |
| `staff` | 五线谱 / 混排 | `preset: "musicpp"` |

编辑器里**主题由排版模式决定**（展开 → projection、原样 → print），切模式按钮就是整层切换；
每个主题一层用户规则，设置面板的「恢复本档默认」清的就是当前那一层。

## 6. 适配器的判据

- 契约沿用：**painter 构造之后、`resize` 之前调**；简谱构造字号取 `jianpuFontSize(sheet)`。
- 简谱原样档不单独设标题/词曲字号，缺省按出厂比例 48/28、36/28 取整派生（`jianpuSizes`）。
- 文本谱的字号面板给的是 pt，但它整套尺寸不由一个基础字号派生：`style/pu.ts` 只给出 `digitFontSize`，
  由 `PuPainter.resolveScale` 换成**整体缩放**（分母由 `digitFontSizeOf` 从 `digitInkHeight` 反推，含谱面指令）。
  叠放顺序：`metricsFor(方言)` → `pu.overrides` → `applyDocOptions` → 面板那层。
- 成书的 `fontSizeFor` 把墨迹高实测反算成字号（Times 数字 ≈ 0.66em、宋体汉字 ≈ 0.9em），`rebuild.mjs` 也经 `window.__book` 用它。
- `style/book.ts::applyBookPreset` 里有几个**手调常量**，而 `bookstyle.json` 是 `stats.ts` 实测产物——默认值必须写在代码里，否则重跑生成脚本就丢。
- 「改这几个常量会牵动全书断句」（弧高 → 行高 → 每页行数 → 重排），动完必跑 `rebuild.mjs` + `line-check.mjs`。

## 7. 回归

样式层一动就会牵动全书版面，**必须拿既有基线把关，零变化才算过**：

| 脚本 | 把关什么 |
|---|---|
| `node scripts/style-snapshot.mjs --diff=<基线>` | 各档排版器实际拿到的 `LayoutOptions` / `PuMetrics` / `MixedOptions` 逐字段（浮点尾差也算） |
| `node scripts/jianpu-svg-dump.mjs --diff=<基线>` | 简谱引擎各格式逐页 SVG 指纹 |
| `node scripts/mixed-tree-dump.mjs --diff=<基线>` | 混排逐页指纹 |
| `node scripts/pptx-ref-check.mjs` | 拆开导出的 .pptx 量几何，与 2019 年成品 ppt500 同一套判据 |
| `node scripts/page-check.mjs` | 分页版面（越纸 / 谱行相压 / 压页脚 / 行内歌词相压 / 展开档结构） |
| `node scripts/line-check.mjs` | 成书断句 D1~D10 + 版面 V1~V13 + 全书基线（先 `rebuild.mjs`，另 `cmp` 两份 `rebuild-drawlist.json`） |
| `node scripts/pptx-check.mjs` | 原样/展开两档版面 |
| `node scripts/zoom-check.mjs` | 四档纸张宽度一致 + 缩放 |

## 8. 还没做的

- **书样式表的文本语法**（`book.jpcss`）：规则目前只能写成 JSON / TS 对象，见 [待办.md](待办.md) §2.3。
- **页位 / 段号限定的消费者**：对开镜像页边距仍由 `BookStyle.page.mirror` + `pageMargins()` 管，段号样式没有引擎读。
- **「校对对照」主题**：识别叠加视图（按源图坐标定位）不经这四把尺子，不是样式层的消费者。
- 文本谱已解析但未实现语义的 `Space:` / `Off:`，要接成曲内覆盖层。
- 面板暴露的只有字号 / 纸 / 配色；`overrides` 目前只能手写进用户层数据。
