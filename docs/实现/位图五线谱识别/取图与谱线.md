# 取图、去倾斜与谱线（位图五线谱识别）

> [位图五线谱识别](../位图五线谱识别.md)的分篇。

## 取图：`rasterpage.ts`

**不复用 `src/omr/decode.ts`。** 那条是给简谱光栅路写的，两点不合用：
它靠 `OffscreenCanvas`（浏览器专属），而本模块要能进 `src/cli/index.ts` 那条纯 Node 链；
它把整页缩到 `PDF_W = 2000` 宽，而合唱谱原始就是 1917 宽、线距 18px，
再缩一道符头与谱线就分不开了。**位图路按原始像素识别，一格都不缩。**

pdf.js 在 Node 下对这批 ImageMask 直接返回逐行 1-bit 打包的字节，
解包即可——**不需要 canvas**。

### 三种数据形态靠**数据长度**分辨

`ImageMask` 根本没有 `kind`，而长度是三者唯一都给得出、且互不相同的量：

- **ImageMask**（无 `kind`）：逐行 1-bit 打包，置位 = 盖住 = 墨。干净位图那一档是它。
- **`kind: 1`（GRAYSCALE_1BPP）**：同样 1-bit 打包，但置位 = **白**。Xerox 扫的那份是它。
- **`kind: 2/3`（RGB/RGBA）**：每像素 3/4 字节，先算亮度再 Otsu。JPEG 扫的那份是它。

认错**不报错**，只得一幅噪声——这正是要防的那种静默失败。
所以取完按墨迹占比自检一次极性：整页乐谱的墨不可能过半（实测约一成），过半就整幅取反。

## 去倾斜：逐斜率数「能看到几条谱线」（`rasterpage.ts::deskew`）

后面每一步都建立在「谱线是一整行几乎全是墨的横带」上，页面一斜横带就抹平了
——真扫描件倾斜 3~4 px，`findStaffLines` 找不齐谱线，整条链跟着废。

判据是 OMR 里的老办法：谱线与扫描行平行时，行投影在谱线处形成又高又窄的尖峰。
实现上只对**墨点**做直方图，不对每个候选角度重排整幅图（一页的墨约一成，
逐斜率算一遍是几十万次加法，四十个候选也就千万级；列再抽稀一半）；
定下来之后**按列整像素错切**，不旋转也不插值——位图是 1-bit 的，插值只会把谱线糊宽。

三条都是拿页面换来的：

- **门槛必须取高（0.75）**，不能照搬 `staffline.ts` 那边的 0.3。门槛一低，
  曲线是**反的**——谱线越糊、过闸的行反而越多（歌词行被算进来了）。
  实测宁静 p2：0.3 门槛下 s=0 处 145 行过闸，而歪到 ±0.004 时有 341/349 行，
  「最优角度」于是指向歪的那一边；0.75 门槛下只有真谱线过得了闸，峰又尖又正。
  一度改用行投影的**平方和**当陡峭度（文献里的常用法），一样会被歌词行带偏
  ——破碎那份扫描件的两页直接顶到量程 ±0.01。
- **错切方向别弄反**。估计器里像素 (x, y) 记在直方图的 `y + s·x` 行，
  所以校正后的图要满足 `out[y] = data[y − s·x]`；反过来写是把倾斜**加倍**
  （实测扫描件的谱行从 63 掉到 40，比不做还差）。
- **没有明显好过「不动」就不动**（1.15 倍）。封面、纯文字页上这条曲线全是噪声，
  跟着它切只会把图切坏。

真扫描件那一档：音符 **20.4% → 29.8%**、音级 24.5% → 34.9%、小节自检 9.4% → 15.7%；
破碎那份的谱行 63 → 97（每页十二组全找齐），残余斜率一律 0。干净位图那一档不动。

## 弯曲扫描的拉直：**竖着看黑白游程的规律**（`dewarp.ts`）

`deskew` 只会给整页找**一个**斜率，而真扫描件不是斜那么简单——书脊附近的页面是**弯**的，
一页之内谱线的高度随 x 起伏好几个像素，一个斜率对付不了。而后面每一步都建立在
「谱线是一整行几乎全是墨的横带」上，弯一点横带就抹平了（实测主，差遣我 p2
行投影只找出 **35** 条线，页面上明明有十几行谱）。

**判据是逐列的黑白游程**：谱表在**任何一列**上都是「五段黑（线）夹着四段白（间）」，
四段白几乎等长、五段黑几乎等厚——这个规律与页面斜不斜、弯不弯**无关**，因为它是逐列量的。
逐列扫黑游程，凡是能凑出这样一个五连（间距互差 ≤22%、每段黑不超过 0.45 个线距）
的地方，就是一行谱在这一列的位置；线距取全页候选的中位数，偏离两成的丢掉。

> `staffline.ts` 开头那条「不靠白游程众数量线距」的教训在这里**不适用**：
> 那条说的是拿**全页白游程的众数**当线距（符头内部、歌词笔画的空隙数量远超谱线间隙，
> 众数落在 3~5 px）。这里不取众数，而是要求**五连等距**——歌词笔画凑不出五段等距的
> 黑白相间，噪声更凑不出。

### 位移是**二维**的：逐行谱各有各的弯法

把逐列的命中按「x 相邻、中心 y 挨着」串成轨迹（一条轨迹 = 一行谱），
每条轨迹自己一条偏移曲线（本列的 y 减去它自己的中位数，滑动中位数平滑）；
像素落在两行谱之间就按 y 在两条曲线之间**线性插值**，页面上下两头沿用最近那条。

**只给一条逐列曲线（各行谱取中位数）不行**：越靠书脊弯得越厉害，页面上下两端的形变
并不相同，按同一条曲线推，弯得多的推不平、弯得少的反被推歪
——实测那一版扫描件音符 29.95% → **28.97%**。

2026-09-06：轨迹横向允许跨过 `max(24px, 4 × 线距)` 的遮挡。
高分辨率扫描的谱号、调号和密集符杠会连续遮住几格，原固定 24px 将同一谱行切成短碎片。
纵向续接容差不变；推平必须让行投影谱行数**严格增加**，`0 → 0` 不再算增益。
采纳前还要比较推平与不推平经过**去倾斜、补线**后的谱行数，不能丢行。
只比较原始行投影不足以保护 `破碎` 扫描 p3：原始 0 行，仅去倾斜可恢复 12 行，
错误推平虽让行投影增加，后续却只剩 11 行。

推平后的残余弯曲另由 `prims.ts::localLineCenters` 处理：在全行中心附近找短纵向游程，
取横跨两个线距的滑动中位数，至少半窗有证据、偏移超过 1px 才调整擦线中心。
上下邻墨保护仍保留，交叉符干不能被擦断。合成回归覆盖平直/弯曲线、交叉符干、
两行谱跨遮挡续接与无增益时恢复原图：`node scripts/raster-prims-check.mjs`。

### 行投影漏掉的谱行，拿逐列游程**补出来**（`completeStaffLines`）

行投影要求「一整行几乎全是墨」，扫得糊、线又细的底本过不了那道闸——实测
主，差遣我 p4 印着 12 行谱只找出 **7** 行（200 dpi、线距 11.5 px、线断成一节一节）；
而逐列游程在同一页上明明看得见那 12 行（它只要求「这一列上五段黑夹四段白」，
实测每行有 233~318 列支持）。

做法：把逐列命中按中心 y 聚成带（容差 0.4 格），**支持够多**的（取样列的两成半以上）
且**没被行投影的谱行盖住**的，就按各列的中位数合成五条线。

两条讲究：

- **支持要够多**。同一行谱在别的窗口上也会凑出「五段黑」（错开一条线的那种），
  但那些只有十几列支持：实测干净页的假带 11~54 列、真行 260~420 列。
- **谱行要直接给出来，不能把合成的线丢回 `groupStaves` 重凑**。行投影在这种页面上
  留下一地散线（主，差遣我 p4 有 52 条线却只凑出 7 行谱），合成的五条线混进去
  会被那些散线搅得凑不成一组——实测补了 25 条线、谱行只从 7 涨到 **8**；
  直接给谱行才是 7 → **12**（与印在纸上的一样多）。

干净位图那一档**一条都不补**（每一条带都被行投影的谱行盖住了），各档分毫不动。

### 通长的加线会**顶掉一条谱线**，整行谱的音高整段低两级

密集的八度跑动上下各有一排短加线，行投影把它们连成**一条通长的线**
（实测宁静 p5 那条 y=1004、x[244,1906]，只比谱线短一截）。它与下面四条真谱线
恰好等距，`groupStaves` 的「等距 + x 交集」两道闸都拦不住——于是它顶掉了
真正的第五线（1095，被三层十六分符杠压着，行投影看不见），整行谱**上移一条线**，
那一行的音高整段**低两级**：GT `C5 C6 C5 C6…` 被读成 `A4 A5 A4 A5…`。

三条一起才修得干净：

- **`groupStaves` 加一条「五条线的左缘要一致」**（差不超过三个线距）。
  真谱线从系统线起画，一个系统里五条的左缘几乎相同；加线从音符处才起。
- **只把分好组的线交给 `findStaves`**（`staffLines: groups.flatMap(...)`）。
  真正建谱行的是 `findStaves`，它拿 segs 自己再分一次组——不过滤的话
  那条加线照样被它捡回去。
- **四条等距、缺一条就外推补上**：第五条被符杠压着时行投影与逐列游程都看不见，
  但四条等距已经把它的位置定死了；外推之后验一验那儿有没有墨（半数以上的列见到墨才认）。
  只补这一条的话那一行会**整个丢掉**（实测宁静 p5 的钢琴右手行就是这样）。

宁静 P4.1（钢琴右手）**58.0% → 64.1%**，而且**读错 124 → 9**——音高全对了，剩下的是漏检。
全语料音符 71.6% → **72.6%**、按 staff 74.6% → **75.6%**、谱号 86.3% → **87.7%**（认不出 0 行）。

### 分档按**底本的数据形态**，不拿「线宽/线距」当代理量

`chorus-diff` 原来按 `lineThick <= space * 0.2` 分「干净位图 / 真扫描件」。
那个比值随谱线判据一动就翻：实测主，差遣我（线距 11.5px、线宽 2.3px）正卡在门槛上，
改一条谱线判据就整份从扫描档跳进干净档，把干净档的平均从 71% 拖到 55%——
**度量本身在跟着改动漂**。改用 `RasterPage.kind`（`mask` = 排版软件贴的 1-bit ImageMask、
`gray1`/`rgb` = 扫描件），那是底本的事实，不随识别改动。

### 没成组的那些线**要当加线用**，不能整个丢掉

上面把「通长的加线」从谱线里剔掉之后，它就**整个没了**——而它确实是加线：
密集八度跑动上方那一排短加线被行投影连成一条通长的线，上方那些符头
（`C6` 要两条加线撑着）于是一条加线都找不到，`findLegers` 全判否，
**符头认出来了却一个都归不了谱行**（实测宁静 p5 那七个 C6 全是「未归属」）。

所以没进任何一组的行投影线要接着走加线那一路：交给 `sharedLegers` **按符头切成短段**
（`findLegers` 有一道「加线不超过符头宽三倍」的闸，整条通长的过不了）。
`ledgerGrid` 的锚点也要只用**分好组**的线——混进没成组的线，五条一组的下标就全错位。

| | 音符 | 音级 | 小节自检 | 按 staff |
|---|---|---|---|---|
| 丢掉那些线 | 72.66% | 73.23% | 49.74% | 75.65% |
| **当加线用** | **74.99%** | **75.56%** | **51.72%** | **77.98%** |

宁静 P4.1（钢琴右手）**64.1% → 76.1%**（读错 8、漏 123），P4.2 → 93.1%、P3.1 → 92.8%。

### 谱线漏检自检（`scripts/raster-lines.mjs`）

逐列游程还有一个用处：**当行投影的独立证据**。逐列命中里落不进任何已检出谱行的，
按 y 聚成带（二十个以上取样列支持才算），就是「疑似漏了一行谱」。

实测 53 页：补线之前 525 行谱、疑似漏检 10 行（全在主，差遣我：p4 缺 5、p6 缺 3、p7 缺 2，
实地数图 p4 印着 12 行只找出 7 行）；**补线之后 536 行谱、漏检 0 行**——
干净位图、Xerox 扫的破碎、JPEG 扫的主，差遣我，全语料一行不漏。

> **不能拿「逐列看得见几行」直接与谱行数比**：轨迹会被符号打断、带也会被倾斜拆碎，
> 那个数两头都不准（实测干净页 100 行谱只串得出 33 条轨迹、却聚出 175 条带）。
> 只有「落不进已检出谱行的命中」才是硬证据。

### 两道闸：只在**行投影明显不够**的时候动图，动完还要**自己验**

- **动图的前提**：逐列游程看得见的谱行数（轨迹数）比行投影找出来的成组谱行数多出
  四成以上，才判这一页是弯的。差不多的页面（干净位图、只是整页略斜的扫描件）
  交给 `deskew` 就够——无条件推平实测扫描件音符 29.95% → **29.67%**，
  还把「干净/扫描」的分档搅乱了（`chorus-diff` 按线宽/线距分档，推平会改变这两个量，
  主，差遣我 整份从扫描档跳进干净档，把干净档的平均拖到 54%）。
- **动完自检**：照 `deskew` 那条「没有明显好过不动就不动」的规矩，
  拿**成组的谱行数**（不是散线条数）比一比，没多出一成半就整幅还原。
  按散线数判会采纳一批「线更多、谱行没多」的推平，扫描件那一档反而降。
  门槛扫过 1.0 / 1.05 / 1.15：音符 26.92 / 31.11 / **31.11%**。

**实测**（只动真扫描件那一档，干净位图**一个像素都不动**、各档分毫不差）：

| | 音符 | 音级 | 小节自检 |
|---|---|---|---|
| 只有 `deskew` | 29.95% | 34.84% | 16.03% |
| **加分带推平** | **31.11%** | **36.0%** | 15.71% |

主，差遣我 p2 行投影从 35 条线修到 60 条、p4 从 52 到 64；那一份整体音符 27.1% → 30.0%、
音级 34.5% → 36.9%。

## 谱线与基本单位：`staffline.ts`

### **先找线、再从五条一组反推单位**

musicpp `omr/pixel.cpp::findUnit` 的办法是取逐列黑白游程的众数，
假定最多的白色纵向游程是两条谱线之间那一段。**这本书上不成立**：
符头内部、歌词笔画之间、和弦图格线的小空隙数量远超谱线间隙，
白游程众数实测落在 3~5 px，而真线距是 17~19 px——差了四倍，后面所有门槛全废。

反过来做就没这个问题：谱线是「一整行几乎全是墨」的横带，行投影一次就找齐
（实测宁静的伯利恒 p1 一次找出 50 条 = 10 行谱，分毫不差）；
五条一组分出来之后，组内相邻线的间距就是线距，取全页中位数。

### 端点要**连续有墨**才算

行投影见到一个墨点就算起点的话，系统的花括号、乐器名擦到谱线那一带
就把谱行的左缘拉到页边（实测宁静 p1 十行谱里六行的左缘跑到 x=2），
`makeSystems` 判系统线、`makeBars` 切小节全跟着偏。要求连着若干列有墨之后，
系统数从 85 降到 26（100 行谱）。

## 去谱线：**上下都没墨才抹**

经典的「保符号去线」判据：谱线那一带的某一列，紧邻的上方与下方都是白的，
才说明这一段是**孤立的谱线**；只要有一侧连着墨，它就是某个符号穿过谱线的那一截。

一度只判「纵向游程短」，那会把**骑在谱线上的细笔画一起抹断**：
拍号数字、休止符、谱号都压在谱线上，笔画细的地方游程正好短，一抹断成两截，
同一个符号按断法不同散成好几个形状类（四分休止散成四类、拍号数字散成一堆碎块）。
换判据之后 4/4 拍号、低音谱号、升降号都完整了。

## 几何原语：`prims.ts`

### 靠**游程**分笔画，不靠连通域

直接对整幅图做连通域没有用：一行谱的五条线、压在上面的符头符干符杠、
穿过去的小节线全连成**一个**块。得先按「这个像素属于横笔画还是竖笔画」分开：
纵向游程短的是横笔画、横向游程短的是竖笔画、两个方向都在符杠区间的是符杠，
分完再各自做连通域。

### 「细」的上限**卡在谱线与符杠之间**

谱线约 0.15 个线距厚，符杠约 0.5 个。一度写成 `lineThick * 3`，
那正好撞上符杠的厚度——符杠混进横笔画、与它压着的谱线连成一块，
块高一超限整条谱线跟着被剔掉（宁静 p1 五十条谱线只剩十一条，且都不是谱线）。
改成 `max(3, min(lineThick*2, space*0.4))`。

### 笔画要沿自身方向做**闭运算**

符干穿过谱线的那几个像素，纵向游程一下子变成整根符干的长度，于是被踢出横笔画
——一条谱线因此被每根符干断成十几截，后面「长度 ≥ 最长横线的 35%」那道闸一截都过不去。

### 笔画要判**孤立性**

谱号的中央竖笔、升号的两道竖笔、拍号「4」的竖笔，横向游程都很短，
一律被当成竖笔画抽走，于是**符号被自己的笔画切开**——高音谱号切成上下两半，
位置自举取到的一多半是它的上半截，高度不到 3.8 格，整批误判成低音谱号
（你要等候 76 行谱认出 69 个「低音谱号」）。

判据：沿笔画取样，两侧（横段则上下）的邻墨超过一半就判它属于某个符号，不当原语。
真符干、真小节线两侧是空的，只在符头、符杠那一小截有邻墨。

### **加线免检孤立性**——它只出现在谱线网格的延长线上

加线总有个符头压在上面，孤立性判据一律判它「属于某个符号」，
于是既抽不出来（`findLegers` 没得用）、也抹不掉（符头连着加线，
宽度从 1.3 格涨到 1.77 格，字典里凭空多出两个三百多实例的「符头」大类）。
加线有一条更硬的判据：**只可能出现在第一线上方或第五线下方整数个线距处**（容差四分之一格）。

### 符杠要够**扁**

光靠「够长、不太高」拦不住符头：实心符头约 1.3×1.0 个线距，
纵向游程落在符杠区间里、横向游程也过线，宽度还差一点点就够。
符杠是 3:1 往上的长条，符头是 1.3:1 的椭圆，长宽比一刀分得开。



## 分系统：按**左端系统线的墨**，不按连通块

`prims.ts::groupByLeftInk`。`makeSystems`（`staffomr/page.ts`）原来只认两样标记：
挂了 `SysLine` 的竖段、字形是 `bracket`/`brace` 的符号。位图路上这两样都靠不住：

- **方括号的上下衬线会把粗竖笔与细系统线连成一块**，那一块宽 20px、
  超过竖笔画的宽度闸（`thin*2` ≈ 9px），于是 `findPrimitives` 一条 `SysLine` 都抽不出来；
- 位图路没有字形，`bracket`/`brace` 这两个 code 一个都不会出现。

结果是**每一行谱各自成一个系统**——实测望十架那份 99 行谱碎成 **81 个系统**
（正确是 25 个上下）。系统一碎，`alignSections` 只能对上 GT 里那两个单行段
（GT 2695 音只对上 187 音），`buildScore` 也接不起来（游离音符 **446** 个）。

**改按墨判**：两行谱之间的缝里，逐行看「谱行左缘那一小条窗口里有没有墨」，
够九成就判这两行连着、属于同一个系统。窗口开在左缘往外两格、往里半格
——歌词与力度记号都在更右边，页边框在更左边，都进不来。

这条判据**不受碎块影响**（不管括号断成几截，墨还在），实测三个阈值
（窗口往外 1/2/3 格、成数 0.8/0.9/0.95）**结果完全一样**，说明分得很开。

| | 之前 | 按左端墨 |
|---|---|---|
| 望十架.pdf 系统数 | 81 | **25**（p1 `1 1 4 3`、p2 `4 4 4`、p3 `4 4 5`、p5 `4 4`） |
| 望十架.pdf 音符 | 14.0%（游离 446） | **27.4%**（游离 88） |
| **真扫描件那一档** | 33.01% | **40.57%**（含游离 28.65% → 34.87%） |

干净位图那一档**一分不动**：那些底本的系统线本来就抽得出来，两条路给出同一个分组。

> 顺带修了 `makeSystems` 的一处先来后到：**罩得多的标记要先分组**。
> 同一个系统上既有罩全系统的方括号、也有罩钢琴两行的花括号，
> 花括号先把那两行占走的话，剩下的行就各自成系统（实测望十架 p3
> 四行的系统因此裂成「2 + 1 + 1」）。

> **试过按连通块找「系统括号」，不够用（已撤）。** 照 `findBraces` 放宽两处
> （允许压在谱行左缘上、罩几行都算），再把共线又上下贴着的碎块并回一个：
> 望十架一份从 81 个系统降到 49 个，扫描件那一档 33.01% → 35.05%
> ——比不做好，但远不如按墨判的 40.57%。括号碎得比预想的厉害，
> 并块的规则每补一条就多一处要调的阈值，而「墨连不连着」一条就够。
