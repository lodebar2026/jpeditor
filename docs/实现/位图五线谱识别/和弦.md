# 和弦符号（位图五线谱）

判据在 `src/rasteromr/harmony.ts`；挂到音符上那一步复用矢量路的
`staffomr/textanalyze.ts::attachHarmonies`。

独唱谱（领唱谱、诗歌本式的五线谱）在谱表上方印和弦字母：`C`、`Am`、`G/B`、`D7`、`E/G♯`。
矢量路早就认（靠 PDF 的文本层），位图路一处都没有——全仓从来没有一行给
`StaffNote.chord` 赋过值。

## 一条带 → 一簇一条 → 按文法切成记号

架构照歌词那条路：切条 → 按**条的内容指纹**寻址的离线 OCR 缓存
（`gen-rasterharmony.mjs` → `rasterharmony.json`）→ 识别时纯查表。
缓存的值类型与歌词共用（`OcrChar`）。

带的窗口是顶线上方 **1.0 ~ 3.2 个线距**。下界留 1.0 格是因为贴着顶线的是符头、加线、
符杠的梢，收进来会被当成和弦字母；上界 3.2 格罩得住字（《坚固保障》和弦印在顶线上方
1.6 格处、字高约一格），再往上是上一个系统的歌词。

### 定位自己做，**不请 DBNet**

声部标签那条是请的（`stafflabel.ts`），因为标签带里压着上一行谱的歌词与弧线，
几何闸分不开。和弦带里只有一行和弦字母，列投影一打就是干净的簇：实测《坚固保障》
三条带，**簇内字距 ≤10px、簇间 ≥16px**（线距 15px），中间空得一干二净，门槛取 0.75 格。

而 DBNet 在这个尺度上反而框不全——整页 42 个和弦只框出 30 个，
`Dm`→`om`、`G C`→`C10`、`E/G♯ Am`→`E1`+`An`+`1`。逐簇裁紧、各自送 rec，
短拉丁串就认得准了：42 个里只错两处（`F`→`卜` 两次、`E7`→`Ei`）。

### 切成记号靠**和弦文法**，不靠簇的边界

簇偶尔会并掉两个挨得近的和弦（实测系统三末尾 `Dm G` 只隔 9px，系统一 `G/B C` 同理）。
`CHORD_TOKEN_RE`（**从 `textanalyze.ts` 导出复用，别抄第三份**）要求根音是大写 A–G，
从左往右贪心地咬，`DmG` 自然断回 `Dm` + `G`。

形近纠正只敢在和弦这个小字表里做：`卜`/`ト`/`下`/`尸` → `F`（这几个字在和弦记号里
根本不存在），**结尾**的 `i`/`í`/`j`/`l` → `7`（只改结尾——`dim` / `min` 这些后缀里的
`i` 在词中间，那里一改就把后缀毁了）。

## 先认领，再找符头

和弦带里的块在**符头检测之前**就按条的盒认领掉，并从候选里剔除（孔洞那一路的
`takenBoxes` 也要带上它们——`D`/`G`/`B`/`A` 的内腔就是洞）。

`C`、`D`、`G` 都是圈，正落在空心符头那一档里（`HOLLOW_BAND` 上下各让三格）——
实测《坚固保障》整页因此多出六个 D6/E6 全音符、四个 C3 四分音符。从前是拿
`staffBandOnly` 把带外的墨整片抹掉换干净的，那是遮挡不是识别，和弦与歌词一起没了。

**只在缓存命中时才认领**：合唱谱那批没有和弦带缓存，这一段对它是空转，基线分毫不动。

## 挂到音符上：**先定谱行，再在行内找音符**

`attachHarmonies` 原来是「下方所有谱行里 x 最近的那个音符」，一页只有一行谱时看不出
问题；一页三个系统时就串行了——下一个系统同一个 x 上的音符离得一样近，抢走了本行的
和弦（实测《坚固保障》42 个和弦只落上 17 个，而且整片挂到别的系统去）。
谱行取**下方最近**的那一行，与 `buildLyricLines` 给歌词找谱行的规矩正好对称
（那边是上方最近）。

位图路调用时传 `merge = false`：记号已经按和弦文法切好了，再按「左右相接」拼一次
会把谱面上挨着印的两个和弦并成一个（42 个只剩 32 个）。矢量路仍要合并——
它的根音与后缀是两个文本对象。

## 和弦行排得高：整行重切

带是顶线上方 1.0~3.2 格，列投影只看带里的墨。《圣哉三一歌伴奏》音符高、和弦行跟着抬到
顶线上方 2.7~4.7 格，带里只剩字脚：条的左右边界按字脚定，♭ 的肚子、B♭7 的「7」、
B♭/F 的 F 横画都在带外被切掉，OCR 把 E♭ 读成 `El`、A♭ 读成 `At`，30 个和弦对上 10 个。
原有的「碰到带顶往上长」（`GROW_UP`）只长高、不管左右。

修法：一行里**往上长出一格以上**（`GROW_BIG`）的条占多数（且至少两条），就把带顶挪到它们
长到的最高处再切一遍。只长几个像素的很常见（坚固保障一行 11 条全顶到、只长 0.2 格），
那不重切，其余曲子的条一个像素不变。30/30。

## 和弦与文本分开

带往上挪后会收进文字：词曲署名「(John B. Dykes)」、结束记号「Fine」（后者原来就被读成 F 和弦）。
不靠条数、位置去挡，而是**认出来是文本**，单独交出去（`RasterPageResult.harmonyTexts`），
不进和弦、不认领墨迹。与简谱路 `omr/chordline.ts` 同一套：

1. **记号词**：`blankNonChord` 抹掉的段落词、跳转记号（Fine、D.C. al Fine、To Coda）、调号拍号、方括号注。
   顺带修了那边的次序：段落词表里也有 fine/coda，先抹它会把 `D.C. al Fine` 拆散、`al` 留下；
   改成跳转记号在前（简谱 measure-all 逐项不变）。
2. **根音大写、贪心咬**，咬不动的跳过：小节号、延长记号读成的 `S`（`DS`）是杂字，只跳过、不当文本。
3. **与小写字母粘连的是单词**：记号前面紧挨小写字母（上一个记号的尾巴除外，`DmG`），或后面紧跟咬不进的
   小写字母，整串收成文本。汉字串同样收成文本。
4. **按整行判**（`harmonyLine`）：署名被列投影切成 `(John`、`B.`、`Dykes)` 三条，中间那条单看是 B 和弦。
   一行的条合起来，看和弦记号覆盖了多少字——两个以上和弦要占 85% 以上，只有一个和弦时不许有别的单词
   （同 `isAnnotationLine`）；记号词与数字不计。不达标的整行归文本。

## 和弦行被高音顶上去（2026-09-25）

《恩友歌伴奏》右手音符用到 C6、D6，和弦行在顶线上方 3.3 格开外，带顶（3.2 格）切掉字的上半，
带里只剩符头与小节号的碎块，35 个和弦一个都没切出来。原窗口切出的条不到三条时，把带顶提到 4.5 格
（`BAND_TOP_HIGH`）再切一遍，条多出一倍以上才用它：和弦 0/35 → 32/35（91.4%），独唱谱和弦合计 78.3% → 87.6%，
合唱谱两档不变（没有和弦的谱表多出的条 OCR 读成文本行，不认领）。改完要重跑 `gen-rasterharmony.mjs`。
