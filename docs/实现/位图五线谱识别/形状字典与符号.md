# 形状字典与符号识别（位图五线谱识别）

> [位图五线谱识别](../位图五线谱识别.md)的分篇。

## 形状字典：`rasterglyphs.ts`

键与矢量路不同：那边有字形轮廓，可以拿 `shapeKey`（轮廓归一后哈希）当精确键；
位图没有轮廓，同一个符号每次栅格化出来的像素都略有出入，精确键必然全落空。
所以这边**只有一层**：按 32×32 签名的汉明距离聚类，尺寸当粗筛。
尺寸一律归一到**线距**（同一页上可能有两种谱表大小，实测主治万方 18.5 与 15.6 并存）。

按尺寸分桶，否则是两万块 × 上千类 × 1024 格，跑不完。

`binSig` **必须反向映射**：符头只有 23×18 px，缩到 30 px 是**放大**，
正向遍历源像素时大半目标格一个源像素都摊不到，签名会变成棋盘格。

### 定案三层（可信度递增）

**1. 模板** —— 拿矢量路 `src/staffomr/glyphmap.json` 那 158 个**已全部定案**的形状类比签名。

合唱谱与赞美之泉是**同一系的乐谱字体**（Maestro 一族），而那本的形状类
全部定案、未定 0，并且存着 32×32 签名与 em 归一的宽高（em = 谱表高度 = 四个线距）。
实测尺寸逐项吻合：gClef 模板 2.75×7.45 格、位图实测 2.74×7.51。

> **签名要上下翻。** `shapeSig` 吃的是字形轮廓，那套坐标 **y 向上**，
> 归一时字形的底边落到签名的第 0 行；位图签名是 y 向下的。
> 不翻的话 gClef 的距离是 102（认成 `csymParensLeftTall`），翻过来是 **30**；
> 升号 80 → 46、降号 127 → 52。这一条不是可选项。

距离上限扫过 90 / 130 / 170 / 220，**90 最好**（音符 28.8 / 28.2 / 28.3 / 28.4）。
模板**只取 Maestro 一家**：放开到 Opus、Anastasia 更差（57.9% → 56.8% / 56.8%），
那两家的同名字形形状差着一截，放进来只是给最近邻搜索添了一批更像噪声的候选。

### 谱号：先把碎块并回一个盒，再拿模板签名验

谱号常被**自己的笔画**切开——中央那道竖笔横向游程短，孤立性判据拦不住时就被当成
竖笔画抽走（实测宁静 p7 的高音谱号断成 1.43×2.59 与 2.76×2.65 两截）。
按连通块判必然错：剩下的上半截高度不到 3.8 格，整批误判成低音谱号；
更糟的是 2.76×2.65 与 Maestro 的 fClef 模板（2.84×3.34）尺寸还挺像，字典也认成 fClef
——**认错比认不出来更糟**，整页的音高全偏。

`bootstrapClefs` 因此先把**x 上重叠的碎块并回一个盒**（谱号的碎块彼此在 x 上重叠，
后面的调号升降号在 x 上是分开的，并不进来），再拿模板签名比一次；比不出来才退回按高度分。
识别时谱号**盖过字典**：落在合并盒里的字典结果一律作废，那是被切开的半截。
实测宁静 p7 从 `FFF?f` 修成 `GGFgf`，全语料音符 61.1% → **64.9%**、音级 62.1% → 66.2%。

同一招推广成一道通用的**碎块合并**：x 上重叠、上下又贴着（不到 0.4 格）的未识别块
并起来再查一次字典，查得到才认。

> **休止符与升降号也照这个套路试过「位置先验 + 模板匹配」**（休止：谱表带内扣掉
> 符头/符干/符杠之后按墨迹列成段取盒；升降：符头左边两格同高度的窗口），
> **不划算**：匹配本身是对的（距离 25~44，很准），但那些符号**字典本来就认得出**
> ——净增几乎为零，总体还略降（音符 65.13% → 65.08%）。
> 谱号那一路之所以值，是因为它被切开之后会**认错**；休止与升降不会。代码已撤。

### 半/全休止要按**位置**再验一道

它的字形是个 1.27×0.51 格的小实心矩形，位图上这种碎块一大把（符杠断头、
粗横笔的一截）——实测宁静一首认出 43 个、全部被采纳，而谱面上根本没那么多。
它有一条硬位置：**半休止坐在第三线（中线）上、全休止吊在第二线下**，
块的纵向中心离那两条线不超过半格。加这道闸之后 43 → 5，音符 56.6% → 57.9%。

**2. 位置自举** —— 谱号、调号升降号在谱行开头的次序是刻谱的铁律。

- **谱号**：每行谱最左边（左端起四个线距以内）、又高（≥1.8 格）**又宽**（≥0.8 格）
  的那个块。宽度那一条不能省：系统线与花括号又高又窄，每次都比谱号高
  （实测取到 0.26×5.74 那种）。高音/低音按 **3.8 格**分，两类之间没有重叠。
  374 行谱只漏 20 个。
- **调号升降号**：紧跟谱号、高 1.8~3.6 格、宽不到 1.5 格。
  升与降靠**墨迹重心的高度**分——降号是上面一根细竖、下面一个胖肚子，
  重心偏下（实测中位数 0.594）；升号上下对称，居中（0.490），门槛取 0.57。
  **不自举还原号**：它与升号都重心居中，只剩宽高比可分（0.36 对 0.276），
  那是一条连续谱、分不干净；而调号里本来就几乎不出现还原号。
  自举只该断言它分得清的事。

自举**按类投票**（票数不到三票、或不到类实例数四成的不算）——
谱号取不到时，最左那个高块可能是调号升号。

**3. 人工小表** —— `rasterglyphmanual.json`，压在前两层之上。

`findBlobs` 的宽高**分别**设限（宽 6 格、高 9 格）：高音谱号 2.8×**7.5** 格，
共用「六个线距」的上限会把整页的谱号挡在外面，`bootstrapClefs` 一个也取不到。
花括号（1 × 15.6 格）仍被高度那一档挡住。

## 拍号：位置自举 + 模板验（字典里一个类都没有）

`rasterglyphs.json` 里 4144 个类**没定名**，拍号一个都没定——全语料拍号识别率
本来是 **0%**。这批曲子恰好都是 4/4、下游按缺省当 4/4 办，所以没露馅；
换一首 3/4 的就整首错。

照谱号那条路走：按位置圈出候选 → 并回碎块 → 拿模板签名验。四处讲究：

- **逐列都试，不能只试最左那一列**。行首除了拍号还有谱号切下来的碎块、
  字典没认出的调号升降号，最左那一列往往是它们
  （实测你要等候 p2 最左是谱号的下半截，真正的 C 拍号在它右边两列开外）。
- **聚列要容 0.4 格的缝**。C 拍号被自己的笔画切成好几块
  （实测破碎 p2 那个 C 是 0.76×2.16 / 0.64×0.93 / 0.58×0.12 / 0.41×0.58 四块），
  严格 x 重叠并不回来；0.4 格并得回来又并不进调号（调号离拍号有一格半以上）。
- **两个数字要按中线几何切，不按碎块自己的位置分上下半**——碎块的盒互相重叠
  （实测上半那块高 2.76 格、已经探进下半的地界）。拍号的版式是死的：
  上面那个坐在第五线到第三线之间、下面那个第三线到第一线。
- **字典认走的也要进候选**（谱号与调号升降号除外），拍号**盖过字典**：
  C 与字典里的 `csymParensRightTall`（大括号）形状相近，认错了照样要能被盖过。

距离上限单设一个 **180**，比通用的 `TEMPLATE_DIST`（90）松得多：
拍号被**五条谱线横穿**，去线在它身上切了好几道口子，退化比谱号重
（实测宁静那个 4/4 上下两半到 `timeSig4` 是 104 与 95，破碎那个 C 到
`timeSigCommon` 是 168）。松得起，是因为位置先验很硬。

四首干净位图全部认对（宁静/主治万方 4/4、破碎/你要等候 C），**拍号 0% → 100%**。

## 升降号：**被抽走的那道竖笔要并回来**

降号是「一根细长的竖笔 + 底下一个小肚子」。竖笔沿途两侧都空着，
`isolated` 判它是原语、`findPrimitives` 把它抽成竖段，`blobImage` 随后照段抹墨
——剩下的只有那个 **0.58×1.05 格**的小肚子，字典当然认不出
（实测破碎 p4 y=314 那行的调号降号：竖段 x=113 y[285,324]，块只剩 [117,304]）。

这一条把**调号**打得很惨：破碎 105 行谱有 **31 行**一个调号升降号都没认出来。

修法照「碎块并回再查」那一条，只是这回要并的是**竖段**：小肚子大小的未识别块，
左缘一带紧挨着一条比它高、上端还探到它上方的竖段，就把两者的盒并起来重查
（字典不认再拿模板验，上限放到 120——并出来的盒是块的包围盒加竖段中心线拼的，
边界不如原块齐整）。并完要把那条竖段**从 `vSegs` 里摘掉**，
不然 `findStems` 会拿它当符干、`findBarlines` 会拿它当小节线。

还原号也是同一个病，只是它有**两道**竖笔：左边那道与横笔连成块、右边那道被抽走
（实测破碎 p10 那个还原号剩下 [582,1005] 0.53×2.34 格的块 + 竖段 x=593）。
所以竖段在块的**左边或右边都要并**，尺寸按升降号卡（并出来 0.4~1.7 格宽、1.5~3.6 格高）。

模板距离上限 **90**。扫过 60/90/120：60 会把刚补上的调号又弄丢
（破碎调号 111 → 87、降号块 123 → 99），120 与 90 的临时升降档一样（都是 73.5%）
但凭空多出的「还原号」更多（破碎 121 vs 100）。

破碎调号漏行 **31 → 1**（105 行谱）、挂到音符上的临时记号 35 → 50。

> 副作用是**认出一堆没人认领的还原号**（破碎 100 个，GT 只有 24 个）。
> 它们绝大多数既没挂到音符上、也没进调号，`keyFifths` 本来就不计本位号，
> 逐音比的「凭空多出」也稳在 4 个——**不落到输出上**。真要收拾，
> 得先解决「符头没归到谱行」（见[符头与加线](符头与加线.md)），那才是它们无人认领的原因。

## 降号的盒要收到**下面那个肚子**上

降号的音高位置是肚子，不是盒中心：字形是「一根竖笔往上伸 + 底下一个肚子」，
Maestro 模板 0.84×2.36 格，肚子只占下面一格左右。而 `analyzeAccidental`
判「这个记号属不属于那个符头」用的是**盒中心与符头中心同高**（容差四分之一格）
——实测降号的盒中心比符头中心**高 0.55 格**，16 个里**一个都过不了**那道闸；
升号与还原号上下对称（中位数 0.03 格），33/36 与 10/11 都过。

位图这边的 `Sym.py` 是从盒算的（`adapt.ts` 造的是假字形），所以把盒收到肚子上
最省事（从盒顶往下四成五起）：`py` 跟着落到肚子中心，`overlapY` 与 x 上的判据都不受影响。
**不动 `staffomr`**——那边的 `py` 从真字形来，两条路的成因不是一回事。

这一条把临时升降从 55.1% 抬到 **67.3%**（降号漏检 8 处 → 2 处）。

> **模板不是用来「认得更准」的，是用来「把并回来的碎块认出来」的。**
> 逐音比下来，临时升降号的错法**全是「没有」——零个种类认错**
> （GT 0→没有 11、GT −1→没有 8、GT 1→没有 3），所以模板在**归类**那一步
> 无用武之地：符头左边那个窗口里的块已经被字典认走了大半（56 个里 47 个），
> 模板只多认 7 个、距离 119~378，多半根本不是升降号。
> 有用的是**检出**那一步——并回竖笔之后拿模板验，那才是上面两节做的事。

> **剩下的 26.5% 追到哪儿了。** 逐处查：14/16 是**近旁（左右五格内）根本没有升降号**，
> 1 处认出来了却被判成调号，1 处认出来没标记。而那些「没有」的实地看图，
> 记号明明印着——堵在**符头没归到谱行**上：`analyzeAccidental` 只认
> 带 `Note` 标记的符头，符头没被认领，紧挨它的记号就挂不上，
> 转而落进「紧跟小节线＝曲中转调」那条分支里当了调号
> （实测破碎 p4 x=603 那个还原号就是这么丢的：它右边 [622,634] 那个符头
> 在谱表下方 1.6 格、没找到加线，于是没有 `Note` 标记）。
> **下一步该修的是加线与符头认领，不是升降号本身。**
